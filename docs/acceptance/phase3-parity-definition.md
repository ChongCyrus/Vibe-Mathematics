## 2. ★★ 因此 **parity 必须分三种，且不许混用**

| # | parity 类型 | 对什么问 | 判据 | 能不能做 |
|---|---|---|---|---|
| **P-a** | **代码↔代码 parity** | ★ **monolith 里真的实现了的东西** | 同输入 → 两侧输出/中间状态一致 | ★ **能**（原文 §5 自陈：**行为级一条都还没做**，且**未读那 11,597 行**） |
| **P-b** | **规格↔实现 parity** | ★ **只存在于 13 份 spec 里的行为** | ★ **vmu 是否实现了 spec 所写的行为**（★ 逐条对，**含 `GAPS.md` 的"缺口"） | ★ **能**，★ 但需要一张 **spec 词 → vmu 模块/键** 的映射表 |
| **P-c** | **vmu 新增** | ★ vmu 有、原版**从来就没有**的机制 | ★ **不是 parity 差异**，★ 是**超出**（用户明确允许"**甚至更优越**"） | ★ **单列一列**，★ 不然"覆盖率"的分母会混进原版没有的东西 ⇒ **指标失去意义** |

★★ **裁定（写死）**：
1. ★ **凡做 parity 报告，必须先声明它属于 P-a／P-b／P-c 哪一种**；★ **三者不得混算一个百分比**。
2. ★ **P-b 的"一致"不等于"逐字复制"**：★ 原版是**规格**，★ vmu 是**实现**；★ 判据是**行为是否被实现**，★ 而不是"字符串是否相同"（★ 字符串相同只适用于**提示词内容**那一类，★ 那由 `phase3-parity-prompt-content.md` 负责）。
3. ★ **不允许**用"grep 命中 0"推出"原版没有该语义" ✓ —— ★ 那是**关键词**结论，★ 原版可能**换个词**写了同一件事（1c-B 已具名此边界）⇒ ★ 消解它只能靠**读 spec ＋ 定点读 monolith**。
4. ★ **报"未覆盖"之前，先确认它属于 P-a/P-b** —— ★ P-c 的东西**永远不该出现在"未覆盖"里** ✓
