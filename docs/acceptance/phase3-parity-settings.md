## 3. ★ DEFECTS（按严重度；file:line）

### 3.1 ★★ D1（**最高**）：`defaults.json` 与 `defaults.js` **声明了同一套 43 键** —— 谁是所有者？
- 位置：`vibe-math-vmu/packs/v5r/settings/defaults.json`（43 键）／`vibe-math-vmu/packs/v5r/settings/defaults.js`（43 键）
- 事实：★ **两文件键集合【完全相同】**（`json ∩ defaults.js` ＝ 43/43）
- 风险：★ 若二者**都是手工维护** ⇒ **同一事实有两个写者** ⇒ ★ 与本项目反复处理的"**同一个事实必须有唯一所有者**"同型；★ 若其中一个是**生成产物**（或只是 `import`/`require` 同一份数据）⇒ **则不是缺陷**，但**必须写明谁生成谁**
- ★ **判定所需（我没做，具名）**：读 `defaults.js` 的**内容形态**（是 `export default {…}` 的**第二份字面量**，还是 `import` JSON / 由生成器产出）⇒ ★ **这是 D1 定性的唯一一步，很便宜**
- ★ **诚实标注**：★ 本条是 **"待判定"**，**不是**已证缺陷（我**没有**读 `defaults.js` 的内容；只比了键集合）

### 3.2 D2（中）：**清单层 12 键 与 值层 43 键 互不相交** ⇒ 两套入口，无交叉核对
- 位置：`v5r-core.js:94`（12 键）vs `defaults.json`（43 键）
- 事实：★ **交集为空**（§2.1）⇒ 无冲突 ✓ ★ **但也没有任何机制**保证"某个键**该在哪一层**" ⇒ ★ 同一个键将来若**被搬到另一层**，**唯一的信号就是冲突门**（而它只在**重复**时报）⇒ ★ **无"漏声明层"检查**
- ★ 影响：★ 55 个键（43＋12）分布在两层，读者**必须同时看两处**才知道全貌（本报告的映射表因此必须双列）

### 3.3 D3（低）：原版 `preset.yml` 只有 3 行 ⇒ **"可调项"必须去 `agent.cordis.yml` 找**，而文档里没有指路
- 位置：`vibe-math-v5r/preset.yml`（3 行）／`vibe-math-v5r/agent.cordis.yml`（461 行）

## 4. ★ 新版更好的地方（照任务书口径："声明/派生而非硬编码"算更好）

1. ★★ **pack 默认必须被 `schema.js` 声明**（§2.2：**0 个未声明**）⇒ ★ **默认值不是一个"自由字面量"，而是有声明、有 `hot`/`who`/`doc` 的登记项** —— 这是**结构性**优于"代码里的常量"；
