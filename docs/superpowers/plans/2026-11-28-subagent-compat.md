# 宿主子代理兼容迁移设计与执行计划

**目标：** 保留 V2–V5 数学策略，在已验证的 v2.8.5 加载热修复上实现宿主契约兼容、可重复测试和真实工作流证据。

**架构：** 新建 shared/subagent-compat.js，集中处理 startContinuable 与 startActivation 的差异。四套框架各保留一个小型能力分流入口，旧宿主走原接口，新宿主按需载入共享模块；消息、中断及研究调度仍使用原框架调用链。先接入 V3，通过后逐个推广。

**技术栈：** ES modules、Node assert/test、DSH 0.2.2-rc.1 实际 Electron 宿主；不新增依赖。

## 方案取舍

逐框架重写生命周期会复制协议逻辑；上游 VMU 单轮桥接会改变常驻研究语义。采用能力检测和共享薄入口，集中拥有 Activation 清理、错误传播和请求映射。加载生成器及冻结 YAML 沿用上一阶段成果。

## 全局约束

- 不覆盖上游 main，不提交 Git、不推送、不发布 npm，不覆盖用户配置。
- 请求父 Agent 必须保持真实对象身份；maxDepth 使用宿主配置，不硬编码放宽。
- 首次 Activation 的 delivery 明确为 caller，保留 native subagent/start、subagent/end 驱动；当前宿主冷恢复会重设为 parent 投递，因此首轮静默不代表后续轮次也静默。
- 工具权限请求须被证明实际生效；宿主不支持的限制应明确报错，不静默丢弃。
- 区分模拟契约测试、真实宿主集成、真实模型数学验收；明显费用任务先估算并等待确认。
- 共享模块保持小接口，禁止大规模重构研究策略或提示词。

## 复核重点

1. 已结束 Activation 的 dispose 不影响同 session id 的后续 epoch。
2. 子代理快速结束或创建取消时，路由登记和清理不会遗漏。
3. 配置过滤器、超时和非成功 stopReason 不被吞掉。
4. Windows 空格/中文路径及 Electron ASAR 测试运行可重复。
5. 多根会话隔离，断点恢复不引入无限重试或额外根代理调用。
