# 审计方法论：可复现的守卫、具名红与实测边界

> 面向读者：想理解或复用本仓库验证方式的人。
> 权威索引是 [`AUDIT-CHECKLIST.md`](./AUDIT-CHECKLIST.md)——本文件讲**方法**，那本文件逐条列**守卫与变异**；两者不重复同一句话。
> 文中的命令与路径都可以直接跑；每个数字都应**当场重新派生**，不要照抄本文件里的历史读数。

## 1. 这套方法要解决的问题

三类"看起来通过、其实没验证"的失败：

1. **空过（vacuous）**：断言两边来自同一个来源（同一个变量、同一份读数），恒真。
2. **只数数量**：只断言"共 N 条"，不看内容；删掉语义后计数照旧。
3. **文档漂移**：代码改了，文档/索引里的数字与说法没跟上（本仓库历史上出现过多次）。

对应三条纪律：**断言要有具名失败**、**计数要现取并写明单位**、**没有判别力时如实记录边界**。

## 2. 门禁的组成与计数

```bash
node tests/run-tests.mjs            # 全部作业
node tests/run-tests.mjs --counts   # 打印派生计数（JSON）
node tests/run-tests.mjs --only <子串> --exclude <子串>
node tests/run-tests.mjs --self-check   # 校验门禁自身的诊断/超时机制
```

- **作业计数（job count）** = 套件（suite）+ 探针/变体（probe）。`--counts` 给出三元组 `{"total","suites","probes"}`，这是**唯一权威**。
- **文件计数** = `tests/*.mjs` 的文件个数（含 `*.test.mjs` 与 `*.mutants.mjs`），与作业计数**不是同一个量**。文档里写"多少个测试"时必须说明是哪一个。
- **变体一律算探针，不算新套件**：同一个脚本多带一个参数跑（例如给某套件加 `--self-probe`）是**额外的仪器化运行**，不是新增套件。门禁的作业分类必须是 `kind: 'probe'`；按**文件名**判类会把这个量算错（本仓库真实发生过：一个套件加上 `--self-probe` 后 `suites` 从 44 变成 45）。
- 变体在 `tests/run-tests.mjs` 的 `VARIANTS` 里注册（`{ file, args, expectExit }`），因此**随包可复现**。

## 3. 三种守卫形态（选一种，不要发明第四种）

| 形态 | 位置 | 适合 | 怎么让它红一次 |
|---|---|---|---|
| **套件内行为断言** | `tests/*.test.mjs` | 真实调用后的行为/字段 | 直接断言；配套变异见下两行 |
| **随包变异族** | `tests/*.mutants.mjs` | 单点改坏后**具名**变红 | `node tests/<name>.mutants.mjs` |
| **套件内 `--self-probe` / 变异段** | 套件自身 + `VARIANTS` 注册 | 断言读源码文本、或需要同一批谓词喂坏输入 | `node tests/<suite> --self-probe` |

**具名红要求**：变异必须让**一条具名断言**失败。只看退出码不算——退出码可能是别的断言、也可能是崩溃。检测方式因此是"在 `FAIL` 行里找到那条断言的名字"，而不是"输出里出现过这个字符串"。

两种常用写法：

- **同一谓词，两种输入**：把断言用的谓词抽成函数，正常路径喂真实数据，自探针喂**故意改坏**的数据，要求它翻假。仓库里 `tests/audit-participant-set-parity.mjs --self-probe`、`tests/audit-math-computation-parity.mjs --self-probe`、`tests/math-computation-shared.test.mjs --self-probe` 都是这个形态。
- **忠实副本基线**：变异跑在**副本**上（环境缝指向副本），并且先证明**未变异的副本也是绿的**，否则"红"可能只是副本本身的问题；更强的一步是证明**缝确实被读**（删掉副本里的一个文件后，守卫应以**指向副本路径**的错误失败）。示例：`tests/audit-persona-surface.mutants.mjs`。

## 4. 实测边界：宁可"measured, not proven"

当**不存在**有判别力的单点变异时，正确做法是**记录边界**，而不是把附近能红的断言当成证明：

1. 写清**想要判别的行为**；
2. 写清**尝试过的变异与实测结果**（哪个数字、哪条输出）；
3. 给出**为什么没有判别力**的结构原因（例如：提示只入队、要等下一次提交才可见，所以单点变异后状态面看不到它）；
4. 结论写 **"实测边界（measured, not proven）"**，并列出**可能的提升路径**（改断言面 / 需要产品改动但被否决）。

真实例子见 [`AUDIT-CHECKLIST.md`](./AUDIT-CHECKLIST.md) 的守卫索引：有的条目先被记为"显式有界"，后来找到了判别面（把断言从 `status()` 移到 `report()` 的诊断、并补上"再提交一次"的步骤）就**改成引用**并注明"原裁定已被取代"；也有的条目曾引用一个内容已经变化的草稿，被**发现引用过期**后改为直接引用随包套件；还有的变异族条目被**回退**（前提与两条随包守卫互斥），族计数随之变化——这些都只是**实测事实**，不是缺陷。

## 5. 计数与声称纪律

- **现取，不照抄**：任何数字都要说明**单位**与**工具**。例如"行数（`Measure-Object -Line`）"与"字节数（文件大小）"是两个不同的量；同一次读取里 `bytes=12084`、按 LF 切分是 `76` 行，而某些工具对同一文件会给出完全不同的行数——**先说明工具，再给数字**。
- **同一批对象要同一次运行**：变异族的 `N/N` 与耗时取自**它自己打印**的那一行（`TOTAL WALL TIME …`），不要跨运行拼接；运行之间本身就有负载差异。
- **文档不许与派生值矛盾**：live 文档里出现的每个 `TOTAL <n>` 必须等于 `node tests/run-tests.mjs --counts` 的派生值；**冻结的历史发布说明按名豁免**（豁免清单本身也断言非空）。改动计数后跑 `node scripts/update-doc-counts.mjs`（`--check` 退出 0 即收敛）。
- **范围要写明**：说"全部通过"时必须给出**是哪一批作业**（套件 + 探针/变体的三元组），而不是一个孤立的数字。

## 6. 工具链陷阱（都真实踩过）

1. **非 ASCII 路径**：`git` 默认会把非 ASCII 路径转义后再输出，`git status` / `git diff` 的路径看起来像乱码。要看原样路径用 `git -c core.quotePath=false …`，或让脚本自己读目录。
2. **读文件必须显式编码**：`Get-Content` 不指定编码时会按系统代码页（CP936）解码 UTF-8 字节，**行数会塌陷**、内容会乱。要么显式 `-Encoding utf8`，要么用脚本语言（Node/Python）读字节。
3. **含 CJK 路径的脚本要有 UTF-8 BOM**，或用 `$PSScriptRoot` 取脚本自身目录；否则脚本被以别的代码页解析时路径会损坏。
4. **嵌套 `pwsh -File` 在本环境不可解析**：需要在同一进程里用 `& script.ps1` 调用，避免 `pwsh` 再起一层。
5. **单次 `ENOENT` 不等于文件不存在**：可能是路径拼接、工作目录或编码问题。判定"文件不在"要看**同一路径**的多次独立观测（例如同时用目录列举与直接读取）。
6. **`Select-String` 的模式默认是正则**：要按字面匹配就用 `-SimpleMatch`；否则 `[`、`.`、`(` 之类会被当正则元字符，命中数会骗人。
7. **行尾（EOL）与行号都不能当锚**：`git status` 在 `core.autocrlf` 下**看不见** EOL 漂移（改了行尾仍是 "clean"）；**孤立 CR** 会让 `--ignore-cr-at-eol` 计数失真，也会让 `Select-String` 与 `read`／`ReadAllLines` 报出**不同的行号**。⇒ 改文件时**只认"唯一文本锚"**（含足够上下文以保证唯一），**绝不认行号**；提交前用 `git diff --ignore-cr-at-eol` 核对**真实语义差异**（而不是行尾噪声）。
8. **`-Include` 在非递归路径下不生效**：`Get-ChildItem <dir> -File -Include *.md` 会**静默扫不到东西**（于是"零命中"被误读成"不存在"）⇒ 要么加 `-Recurse`，要么把过滤写进 `Where-Object`。

## 7. 新增一条守卫时的清单

1. 选形态（§3 三种之一），并确定"具名红"是哪条断言；
2. 让变异**单点**、可读、可复现；跑在**副本**上，并保留忠实副本基线；
3. 若是新作业：在 `package.json#files` 登记（若是 `tests/*.mjs`），必要时在 `run-tests.mjs` 的 `VARIANTS` 注册；
4. **重跑** `node scripts/update-doc-counts.mjs` 让文档计数收敛；
5. 在 [`AUDIT-CHECKLIST.md`](./AUDIT-CHECKLIST.md) 增加/更新该行（不变量 + 怎么让它红一次），并在 `docs/release-notes/` 的对应版本里说明**用户可见的变化与验证方式**；
6. 若最终发现**没有判别力**，按 §4 写成实测边界。

## 8. 环境卫兵：被杀死的套件会泄漏临时目录（实测）

- **实测**：本机 `%TEMP%`（`C:\Users\admin\AppData\Local\Temp\1`）顶层曾达 **248,737 项**，其中**我们的套件临时目录 245,288 项**（`vibe-*` 221,939、`v2-fix-*` 23,160、…），**111,223 项早于 24 h**（最早约两周前）。
- **根因**：套件用 `mkdtempSync(join(tmpdir(), '<prefix>-…'))` 建工作区并在 `finally` 清理 ✓，**但被门禁超时 SIGKILL 的进程无法清理**；另有一些套件每次运行创建大量目录 ⇒ 数百次门禁后线性累积。
- **卫兵（`scripts/clean-temp.mjs`，由 `tests/run-tests.mjs` 启动时调用）**：
  1. **清扫**：只删 `os.tmpdir()` **顶层**、名称匹配**从 `tests/*.mjs` 的 `mkdtempSync` 自动提取的前缀**（实测 **88** 个）、且 **`mtime` 早于阈值**（默认 **6 h**，避免误删并发运行的另一场门禁）的目录；`--dry-run` 只打印计划；`--age-hours=N`／`--no-temp-hygiene` 可调。
  2. **临时目录优先落 D 盘**：`D:\_tmp` 可用时把 `TEMP/TMP/TMPDIR` 指向它（`os.tmpdir()` **自动跟随** ⇒ **零产品改动**），不可用则回退，**不硬失败**。
- **自证**：`node scripts/clean-temp.mjs --self-test` 断言"**新鲜目录绝不清理**"、"陈旧且前缀匹配才清理"、"**只匹配精确前缀**"、"前缀表来自套件"；变异家族 `tests/temp-hygiene.mutants.mjs` 用两条**单点**变异（去掉年龄阈值／去掉前缀判断）证明这些断言**按名变红**（实测 **2/2**）。
- **通道陷阱（真实踩过）**：卫生信息**必须写 stderr** —— `tests/run-tests.mjs --counts`／`--json` 的 **stdout 是机器可读 JSON**（`scripts/update-doc-counts.mjs` 会 `JSON.parse` 它），把日志写到 stdout 会让计数刷新直接崩（`SyntaxError: Unexpected token 'r'`）。
- **先查遗留进程，再谈"时序抖动"（实测，task-15）**：一次"门禁红、单跑绿"的**总根源是环境** —— 一只**遗留 DSH 宿主**（`--profile vmfix7`，**两天前**启动、父进程已消失）累计烧掉 **197,410 秒 CPU**（≈55 h；在 4 核机上等于**长期占满一个核**），另有 3 只遗留 `review/l2-*.mjs`。带它时整场门禁 `sum of suite times` **2822 s → 7875 s（×2.8）**、单套件被放慢 **1.3–4.5×**；清掉后同配置门禁 **wall 6705.6 s → 1371.2 s（×4.9）**。⇒ 常规动作：门禁启动时**只读列出**"父进程已消失且命令行属于本工程/团队"的进程（`node scripts/clean-temp.mjs --ps`，`--kill` 必须显式），**绝不自动杀**；判据自带 3 条自检 ＋ 两条单点变异（去掉"父进程已消失"⇒ 自家门禁被误报**按名**变红；去掉命令行闸门 ⇒ 无关程序被误报**按名**变红）。
