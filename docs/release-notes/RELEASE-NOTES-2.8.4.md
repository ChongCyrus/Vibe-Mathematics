# dsh-vibe-math 2.8.4 — 发布说明

> 上一版本：2.8.3。本版是**补丁版**：修正 v5 的**会议看门狗**——它此前会在"已被点名的成员仍在进行中"时就把会议放弃，导致成员的正常发言退化成「会后补记」，并让 `paperEditor="office"` 的定稿被反复拒绝。参数名与默认值、数据格式与目录结构**未变**，DSH 支撑窗口不变，**无需迁移**。

## 概述

- 会议**不再**在"被点名、且仍在进行中"的成员交回发言之前被放弃：这类成员最多把会议续命到停滞预算的 **3 倍**，超过硬界才放弃（真正卡死的一轮仍不能拖住整场会议）。
- 结果是**正常发言回到正常小节**：真机实测修复前一次运行出现 **1067** 次「会后补记」、**863** 次定稿被拒；修复后会议能真正收齐发言，「会后补记」退回为**保险**而非常态。
- `paperEditor="office"` 的定稿闸门因此更容易被真正满足（它要求本张论文至少有 1 条所办消息与 1 次**记录在案**的会议）。
- 文档写明会议何时会被放弃、放弃如何具名、以及放弃**之后**到达的发言如何处置。

## 新增

- 无。（本版为修复版：没有新增参数、字段或工具。）

## 变更

- 会议停滞判定：软界（`2 × activityTimeoutMs`，默认 240 s）内，只要仍有**被点名的成员在进行中**就不放弃；超过 **3 倍**（默认 720 s）的硬界则照旧放弃。
- `docs/final-paper.md` §7 增补"会议何时会被放弃"的口径（含软界／硬界与「会后补记」的关系）。

## 修复

- 症状：成员（含**召集人**）在会议里发言后，纪要里却只留下「会后补记」条目；一次真机运行累计 **1067** 次补记，并且 `paperEditor="office"` 的定稿被 `V5_PAPER_CONSULT_REQUIRED` 拒绝 **863** 次。原因：会议停滞只按"最后一次发言"计时，**不看被点名的成员是否仍在忙**；真机上成员的一整轮常常超过 240 s 的预算，于是会议在看门狗手里被放弃，随后到达的发言只能走补记通道。现在"被点名且仍在忙"的成员会把放弃推迟到硬界（3 倍预算），正常发言因此回到会议的正常小节。守卫：`tests/e2e-v5-round2.test.mjs`（`★ [real1004-stall]`，**源码级不变量**：该分支的真机行为无法在随包套件里确定性触发，故判据是"源码不变量 ＋ 真机复测"）、`tests/v5-institute-fixes.mutants.mjs`（**19/19** 具名红）。

- 迁移：无需迁移。

## 已知限制

- 会议看门狗分支的**真机**行为只能由真机复测确认（随包套件里心跳延时不可控 ⇒ 该分支不能确定性触发；因此守卫是**源码不变量**，这一点已在测试注释与提交信息里写明）。
- **非标准位置的 TeX 仍不会被自动发现**：默认探测只覆盖 PATH 与文档化的常见安装根。
- 随包套件**不覆盖宿主层行为**（例如"中断后调用方被丢弃"）。
- **根代理提问会阻塞整所流程**（运维注意项，不改产品）：长跑时请把问题与验收条件一次说清。详见 [`slv-playbook.md`](./slv-playbook.md) §5。
