# dsh-vibe-math 2.2.1 — 把「全面检查必查清单」作为随包强制流程发布

> 上一版：2.2.0（修复实测发现的提示词身份错乱）。本版**只增加交付物**，不改代码。

## 为什么单独发一版

2.2.0 修掉了一整类缺陷，但更重要的是**这一类缺陷此前没有任何审计维度**：
框架发给每个成员的提示词写错了身份，而当时 123 条断言 + 15 个灵敏度探针全部"通过"。
根因不是某处代码写错，而是**审计本身漏了一整类检查**。

为了让"以后每次全面检查都不再遗漏"成为**可执行、可复核的规则**而不是一句承诺，
本版把 `AUDIT-CHECKLIST.md` 作为**随包发布的强制流程**加进来。

## `AUDIT-CHECKLIST.md` 的内容

- **第一优先：提示词分配与交互内容正确性**（身份分配 / 编制与门槛 / 名称与领袖叙事 /
  交互内容 / 时序与幂等），以检查项清单形式给出，每一项都对应一个具体的历史缺陷；
- **第二优先：把每一条变成会变红的测试**——逐条断言而非抽查、期望值必须能证伪、
  用例互相隔离、**必须保留交互语料**、每个不变式都要有灵敏度探针；
- 并明确列出四种**假绿**的识别点，它们在本次审计中**全部真实出现过**：
  1. 探针的工作目录被百分号转义（Windows 中文路径 + `URL.pathname`）→ 子进程全部启动失败，
     "非零退出"被当成"探测成功"，整份审计是假的；
  2. 某个 e2e 套件**不读** `V5_PLUGIN` → 针对它的探针跑的是**未变异**的插件，恒为绿；
  3. 变异是**语义惰性**的（同一规则在多处重复检查，只削弱一处仍被其它处挡住）→ 误报"盲点"；
  4. 变异引入**语法错误** → 同样是假红。
- 第三优先沿用既有做法（静态自检、需求可追溯、失败路径、全量回归、发布产物自证）。
