# 设计总览（vibe-math-v5r）

> 本目录是预设 **`vibe-math-v5r`**——**v5 的重构预览版**，与 v5 **并存**，用于同机 A/B 对照。
> 本文件只做**导航**与**硬性要求**，**不含实现细节**。

---

## 一、三条硬性要求

1. **v5r 是在 v5 基础上进行若干方面重构的版本。** 它与 v5 并存；两者的行为差异**以本目录的设计基线为准**。
2. **`LEGACY-v5-实现方案（仅供参考）.md` 是 v5 的旧实现方案——仅供参考，不是 v5r 的规格。**
   其中的取舍**不得**当作 v5r 的硬约束；v5r 重构时若与它不一致，**以 v5r 的设计基线为准**。
3. **v5r 的权威设计基线**＝
   - **`MEETING-PLATFORM-RULINGS.md`（设计定稿）**：已定规则（D1–D10）与硬口径；
   - **`MEETING-PLATFORM-PHILOSOPHY.md`（章程）**：哲学、现实制度解剖、原则红线、自检判据。
   专题与实现参考（VOTING／EXPANSION／OVERSIGHT-TIME／SPEC／A／B／C／DECISIONS／GAPS）**按需查阅**。

## 二、文档一览（一句话作用）

| 文档 | 一句话作用 |
|---|---|
| `MEETING-PLATFORM-RULINGS.md` | **设计定稿**：会议平台已定规则与硬口径。 |
| `MEETING-PLATFORM-PHILOSOPHY.md` | **章程**：为什么要有会议、现实会议制度解剖、原则红线、自检判据。 |
| `MEETING-PLATFORM-VOTING.md` | 表决与聚合专题：法定人数、沉默／弃权语义、票与发言分离的补强。 |

| `MEETING-PLATFORM-A-model.md` | 平台模型稿：会议实体、状态机、命令契约目录、权限、引用与观测面。 |
| `MEETING-PLATFORM-B-protocol.md` | 流程与机制稿：按类型的推荐流程、发言机制、引用语义、表决聚合、权限矩阵、反模式。 |
| `MEETING-PLATFORM-C-landing.md` | 落地稿：现状盘点、差距表、分期、守卫与验收判据、兼容迁移、风险。 |

| `LEGACY-v5-实现方案（仅供参考）.md` | **v5 旧实现方案——仅供参考，不是 v5r 规格**。 |

## 三、建议阅读顺序

1. **设计定稿**（`RULINGS`）→ 2. **章程**（`PHILOSOPHY`）；
2. 要落地时看 **`SPEC`** 与 **`C-landing`**（差距、分期、验收）；
3. 要机制细节看 **`B-protocol`**；要模型细节看 **`A-model`**；
4. 要边界与反例看 **`GAPS`**、**`DECISIONS`**；专题问题查 **`VOTING`／`EXPANSION`／`OVERSIGHT-TIME`**。
