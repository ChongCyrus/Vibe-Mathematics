# 第 01 章 · 哲学与红线

**本旨**：说清平台为什么这样设计：谁在其中、谁做决定、什么绝不允许。

**本章权威性**：本章是会议平台的哲学立场与红线的唯一权威；与本章冲突的任何其它说法一律作废。

> 本文只谈**哲学、理念、业务需求**：为什么要有会议、它是什么、它服务什么、它与现实会议如何对应、原则与边界。
> **不含任何实现细节**（不写命令名、参数、错误码、守卫、断言、差距表、行号、代码）；实现层面的约定另见实现参考层文稿，日后再实施。
> 读者假定为：研究所的院士、研究员、临时工，以及代表人类操作研究所的所办。本文力求"读一遍就能明白这个平台想干什么"，不需要任何背景猜测。

## 1. 原始需求（逐字保留要点）与一句话定位

### 1.1 原始需求（照录要点，不改写）

- 把**辩论、开会、表决**等"汇集在一起交流"的机制**统一为一个互动平台**，统称**"开会/会议"**；它们是**同一平台上不同类型的任务**，区别只在于**同一平台下使用不同命令/进行不同操作**；**哲学：尽可能贴合现实会议的组织形式**。
- 平台下按任务类型可用于（不限于）：① **平常会议**（讨论各自研究状况、学术讨论、讨论接下来的任务计划/安排/分配/组织等）；② **为特殊任务设定的会议**（**辩论**、**结题表决**、**结题论文的设计交流**等）。特殊任务可有**专门命令**（如"表决"、**"投所辩论内容的布尔概率估计＋阐明理由"**——这两者当前已有）。
- **院士＝主办方**：定义会议**题目/内容/流程**，并可设定**会议类型字段**（给框架识别用 ⇒ 框架据此决定运行时的特色机制/可执行命令/有效命令/命令权限）；院士**有权决定会议开启与结束**。
- **默认由院士驱动会议**（不是框架驱动）；**框架可以"推荐"大体流程但不强迫**，并应告诉院士**可随时调整/调控**（如延时、下一步执行什么）。
- **院士命令**（不限于）：**邀请发言**（**"邀请内容＋邀请"是一个整体**，带发文内容字段，不是裸动作）、**按顺序依次请人发言**（顺序院士可设，**默认自然顺序**）、**沉淀/等待**（等**在飞**成员飞完决策完，起缓冲作用）、**切换群聊机制模式**（**不设限**的交流群；院士可当**群管理员**设参数如每人可发信息次数、禁言等）、**单次发言版群聊模式**（每人**仅一次**，用于初始让各成员把自己的发言一次性发出来，便于后续轮流或辩论）、**创办投票板**（院士设选项内容与规则：单选/多选、最多选几票/至少选几票、最少收集几票等）、**创办待领任务/创建任务板**、**分配任务给某成员**、**散会**，以及其它一系列**与会议/学术会议/工作会议相关**、**管理会议进行与管理发言**的命令；院士可设**指定命令/机制的时长、何时停止、实时调控参数（如延时）**，可**手动开启或停止**。
- **成员命令**（不限于）：**举手发言**、**在投票板里投票**、**请求认领某任务**等。
- **权限分场合**：不同场合下同一命令权限可能不同；**有些命令的权限是被临时赋予的**。
- **发言支持"引用"**：可指向过去某条发言（**像 QQ 群 @ 某条消息**）。
- **推荐流程（框架建议、院士可改）**：先**"单次发言版群聊"**让成员各自独立发言 ⇒ 再**"轮流发言"**展开辩论 ⇒ 后续**院士自组织**（一般继续下一轮轮流发言）。
- **辩论结束时的汇总规则**（院士手动结束/散会后）：框架同时请每位成员给出**最终评判结果**，按规则处理 —— **m 个 1（或 0）且无 0（或 1）（允许介于 0 与 1 的概率估计）⇒ 最终判为 1（或 0）；否则求平均并更新概率估计**；随后**框架广播**："根据研究所规则，由于…，故最终布尔概率结果更新至…（如 0.6）/判定结果为…（1/0）"给各辩论者。
- **架构定位**：交互系统＝**私发消息系统**（已有）＋**群聊系统**（本手册编制过程群聊，已有，与会议中院士可用的群聊机制相似）＋**会议系统**（本平台）；**具体任务（辩论等）只是它们的用途/使用方式**，系统本身只是**平台**。
- **总哲学**：**尽可能贴合现实，照现实设计、完善、扩充**。

### 1.2 一句话定位

**会议系统是研究所的"议事厅"**：把需要**有议程、有主持、有程序、有留痕**的交流集中到一处，由**院士（主办方/主持人）**决定开与散、定题目与流程，成员在其中**发言、引用、举手、表决、认领任务**；框架**只推荐流程与提供机制**，不代替院士主持，更不代替研究所产生学术真值。

## 2. 系统定位：三个系统，各司其职

### 2.1 三个系统的分工与边界

| 维度 | 私发消息（点对点） | 群聊（本手册编制过程） | 会议（本平台） |
|---|---|---|---|
| 面向 | 一个人对一个人 | 一群人共享过程 | 一群人**议事** |
| 形态 | 私密、不进入公共记录 | 公开但**无程序**，随时可发生 | **有议程、有主持、有阶段、有决议** |
| 谁在主导 | 发信人 | 谁想说话谁说 | **主持人**（默认院士） |
| 时间结构 | 无 | 无 | **有开场、有阶段、有收束与散会** |
| 产出 | 沟通内容 | 过程性记录 | **纪要、决议、表决记录、任务与执行项** |
| 是否裁决 | 否 | 否 | **可以形成"研究所的决议"**（但不产生学术真值） |
| 典型用途 | 单独交办、私下确认、澄清误会 | 日常同步、随手讨论、抛出想法 | 平常会议、学术讨论、任务规划、辩论、结题表决、论文设计交流 |

**边界三条**：① 私聊内容**不进公共记录**（要留痕就搬到群聊或会议）；② 群聊**不议事**（要形成"研究所决议"必须开会）；③ 会议**不产生研究真值**（真值只由研究所既有的验证/裁定制度产生）。

### 2.2 "平台 vs 用途"的区分（本平台的哲学基石）

- **平台**只提供：会议这个容器、以及一套**通用议事能力**（议程、主持、发言秩序、动议、表决、纪要、任务与执行跟踪、档案）。
- **用途**是：平常会议、学术讨论、任务规划、辩论、结题表决、论文设计交流……它们**不是并列的系统**，而是**同一平台上不同类型的会议**，差别只在于**用哪些议事能力、按什么规则用**。
- 因此"新增一种任务"的正常做法是：**定义一种会议类型 + 规定该类型的默认规则与可用能力**，而不是再造一个平台。

### 2.3 什么时候该开会、什么时候群聊/私聊就够（贴合现实）

| 情形 | 现实里怎么做 | 平台对应 |
|---|---|---|
| 需要"研究所集体知道并认可"的结论 | 开会、表决、写纪要 | 会议 |
| 需要多方在同一议题上交换意见、互相质疑 | 研讨/辩论 | 会议（学术讨论/辩论） |
| 需要把工作拆开、定人定责定验收 | 工作会议 | 会议（任务规划） |
| 只是同步进度、知会某人 | 走廊里说一声、群里发一条 | 群聊/私聊 |
| 单独交办、私下确认 | 一对一谈话 | 私聊 |
| **紧急且只涉及一两个人** | 电话/私聊解决，事后补记 | 私聊 + 群聊补记，不必开会 |

> **判据**：**"不开会也能推进吗？"** 能，就别开会 —— 现实里"什么会都开"是最被诟病的组织病，平台不应鼓励它。

## 3. 现实会议的制度解剖 ↔ 平台对应物

> 每条按 **现实怎么做 → 平台怎么办 → 为什么** 三段写。这是本总纲的重点，"全"优先于"简"。

### 3.1 议题与材料
- **现实**：会前定议题、把材料提前发给与会者，让大家带着判断来。
- **平台**：会议由**题目 + 议程（有序条目，可带责任人/时长）+ 材料**组成；材料在会前挂到议题上，成员可提前阅读。
- **为什么**：没有议题的会议会退化成群聊；材料预发让"异步成员"能在开会前把上下文补齐（对代理尤其重要）。

### 3.2 召集与通知
- **现实**：发会议通知（时间、地点、议题、需带材料）。
- **平台**：由主办方**召集**会议；通知"点名邀请 + 议题 + 材料 + 期望"，可对未在场者发出。
- **为什么**：召集是"会议存在"的起点；通知本身就是一条可审计的记录。

### 3.3 主持人
- **现实**：主持人**中立**（不参与争辩的胜负），掌握发言权分配、维持秩序、宣布表决结果；可轮值、可代理。
- **平台**：主持人默认为**院士（主办方）**；主持人决定开与散、阶段推进、发言秩序与规则；可指定**联合主持/纪要人/代理**。
- **为什么**：主持中立是会议可信度的来源；"谁主持"必须明确，否则议事无人收束。

### 3.4 法定人数与点名
- **现实**：清点出席，不足法定人数不能表决（或只能延期/休会）。
- **平台**：会议有**在册名单**与**出席情况**（在场/缺席/迟到/早退/请假）；表决是否需要满足一个**最低参与/最低投票数**由会议的规则决定。
- **为什么**：没有人数概念的"表决"结果不可信；点名也让缺席者有据可查。

### 3.5 发言权与时间箱
- **现实**：主持人给每人发言时间（时间箱），到时提醒/请其收尾。
- **平台**：发言机制与**时长**是主持人可设并可随时调整的参数；框架按时提醒。
- **为什么**：时间箱是维持会议效率最现实的手段；"可以延时"也是主持人应有的权力。

### 3.6 动议与附议
- **现实**：任何人可**动议**（提议做某事/形成某结论），通常需要**附议**才成立，随后进入讨论或表决。
- **平台**：把"动议—附议—进入表决"作为一条正规路径；是否必须附议、附议几人由规则定。
- **为什么**：这是现实议事规则的核心装置，能防止"一个人随口一说就变成集体决定"。

### 3.7 程序性问题（休会/延长/限制发言/散会动议）
- **现实**：会议进行中可提**程序性动议**：休会、延长、限制发言时间、要求散会。
- **平台**：这些是主持人可随时启用的程序动作；成员若被授权也可提出请求（由主持人裁定）。
- **为什么**：议事程序必须能在不终止会议的前提下调整节奏，否则只能"要么继续要么散会"。

### 3.8 秩序维持
- **现实**：主持人不时打断、请人别抢话、限制发言次数、请离席者安静。
- **平台**：发言次数上限、静默、优先发言、暂停举手、清理队列，都由主持人设定；群聊模式下主持人相当于**群管理员**。
- **为什么**：秩序是会议得以有效的前提；把它做成"可调参数"比做成硬规则更贴近现实主持人的自由裁量。

### 3.9 讨论与辩论
- **现实**：讨论是自由交换；辩论有**正反方**、**一问一答的质询**、以及各自的**总结**。
- **平台**：会议类型决定默认结构；辩论可按"立论—质询—反驳—总结"分轮，质询可要求被质询者回应。
- **为什么**：辩论若没有结构就会变成两条各说各话的独白；结构让分歧可见、可沉淀。

### 3.10 表决方式
- **现实**：口头表决、举手表决、**记名表决**、**不记名（秘密）表决**；有弃权；有**异议与少数意见记录**。
- **平台**：表决事项带选项与规则（单选/多选、每人的上下限、最低收集票数、记名与否、轮次、并列处理）；弃权是明确的表态；少数意见可随纪要保留。
- **为什么**：表决方式直接影响谁愿意表达真实意见；"多数通过 + 少数意见留档"是现实里最被认可的做法。

### 3.11 法定门槛与通过条件
- **现实**：事项有通过条件（简单多数/绝对多数/全体一致/最低投票率）。
- **平台**：通过条件属于会议规则；未达门槛要明确记为"未决"而不是"否决"。
- **为什么**：混淆"未达门槛"与"否决"会误导后续决策。

### 3.12 纪要
- **现实**：有人记纪要（谁在何时说了什么、形成了什么决定），**下次会前确认上次纪要**。
- **平台**：会议由**时间线（事件记录）**自动支撑，纪要是它的可读版本；纪要人可由主持人指定；下次会议开场可先确认上次纪要。
- **为什么**：没有纪要的会议等于没开；"下次确认"是现实里保证纪要准确、责任可追的常规环节。

### 3.13 决议与执行跟踪
- **现实**：决议要写清"做什么、谁负责、何时完成"，并在后续追踪。
- **平台**：决议可携带**行动项（责任人 + 截止）**；会议产出的任务进入任务板，可被认领或直接分配。
- **为什么**：**没有执行的决议只是文字**；开会的目的最终要落到"有事被推进"。

### 3.14 休会 / 延期 / 散会
- **现实**：可以中途休会（保留议题与进度）后复会；可以延期到下次；可以散会结束。
- **平台**：休会与复会是明确状态（时长计入会议）；散会是终止；散会后若还要继续议事，**另开一次会议**并保留原会议为历史。
- **为什么**：避免"散会后偷偷继续"造成记录断裂，也让"会议"这个实体有清晰的生死。

### 3.15 例会与临时会
- **现实**：有定期例会（固定节奏、固定议题类型），也有临时会（突发阻塞）。
- **平台**：会议类型里包含性质差异（例行 vs 临时），例行会议可以延续上次未完议题。
- **为什么**：组织需要节奏感；把"例行"和"临时"混在一起会让两种会议都办不好。

### 3.16 列席与观察员
- **现实**：可以有人列席（听、可发言但不表决），如观察员、外部专家。
- **平台**：在册名单与**表决权**分离：列席者可被允许发言、可被引用，但**不投票**。
- **为什么**：让"需要知情的人"在场，同时不让"不承担后果的人"决定结果。

### 3.17 回避（利益冲突）
- **现实**：与议题有直接利害关系的人应回避该项表决。
- **平台**：支持对某人、某项表决的**回避/回避声明**；回避不计入该项的投票数。
- **为什么**：这是研究诚信的现实要求；平台若不支持，回避只能靠口头约定而无法留痕。

### 3.18 档案与可检索
- **现实**：会议纪要、决议、表决记录归档，日后可查。
- **平台**：会议的**产物与时间线**都是可寻址、可检索、可引用的；成员对与自己相关的部分有知情权。
- **为什么**：组织的记忆靠档案；可检索才让"上次怎么决定的"可被回溯。

## 4. 业务需求全集

### 4.1 会议类型与用途

| 会议类型（用途） | 它为什么存在 | 产出什么 | 与其它制度如何衔接 |
|---|---|---|---|
| **平常会议** | 让全所同步各自研究状况、组织工作 | 进展纪要、任务分配、下一步安排 | 衔接任务系统与成员的研究进度 |
| **学术讨论** | 让分歧尽早暴露、互相质疑与启发 | 讨论要点、共识与分歧清单、可选意向表决 | 衔接成果库（讨论可产生待证命题） |
| **任务规划** | 把目标拆成可执行工作并定人 | 任务板、责任人、验收标准、优先级 | 直接衔接任务系统 |
| **组织调整**（编制/分工变更） | 编制与分工是公共结构，需要集体知情 | 决议（增聘/调岗/解散） | 衔接成员管理制度；重要变更由所办执行 |
| **辩论** | 对同一命题存在实质分歧，需要结构化交锋 | 辩论录、各方最终判断与理由 | 与验证制度衔接：辩论结论是**意见的收敛**，不是真值 |
| **结题表决** | 决定"是否结题/是否采纳"这类程序性结论 | 表决记录、决议、行动项 | 与结题制度衔接；不改写研究真值 |
| **论文设计交流** | 定论文结构、口径、分工与图表方案 | 论文方案与写作任务 | 衔接最终论文流程与任务系统 |

> 每种类型都应能回答三件事：**为什么存在**、**产出什么**、**与研究所其它制度怎么衔接**（上表即格式）。

### 4.2 角色与职权

| 角色 | 职权（业务语） |
|---|---|
| **主办方 / 主持人**（默认院士） | 定题目、议程、流程与类型；决定开启与结束；分配发言权；维持秩序；宣布表决与决议 |
| **在册成员** | 发言、引用、举手、表决、动议（依规则）、认领任务、查档 |
| **列席 / 观察员** | 知情、可被允许发言，**不表决** |
| **受邀者**（含所外/临时） | 被邀请就特定议题提供意见；权限由主持人临时授予 |
| **临时工** | 参与讨论与任务，**无表决权**（与其在研究所中的地位一致） |
| **所办（人类代表）** | 代表用户下达与转达指令；在用户明确要求时代行部分主持职责；观察与汇报 |
| **纪要人** | 由主持人指定，负责纪要的准确与完整 |

### 4.3 权利

发言权（含**举手**请求）、**引用**他人发言、**表决**与**弃权**、**动议与附议**（依规则）、**认领任务**、**知情与查档**（与自己相关的部分）、**被通知**（被邀请、被点名、被引用、被分配任务）。

### 4.4 权限与临时授权的业务语义

- **默认权限**：由角色与会议阶段共同决定（同一动作在不同阶段可能合法或非法）。
- **临时授权**：主持人（或获授权者）可把某个动作的权限**临时**授予某成员或某类场合；授权要有**理由**、**生效范围**、**失效条件**（时间到、事件到、或显式收回）。
- **审计**：每一次授权与收回都留痕，可回答"当时凭什么这么做"。
- **业务原则**：*能给临时权限，就尽量不扩大默认权限* —— 默认越小，越不容易出意外。

### 4.5 产物与留痕（以及"不越界"的边界）

- **产物**：纪要、决议（含行动项）、表决记录（含弃权与少数意见）、辩论录、会议任务与执行项、材料附录。
- **衔接但不等同**：
  - 与**成果库**：会议可以产生"待研究的命题/方法线索"，但**不直接写入成果库中的定论**。
  - 与**验证制度**：会议收集意见与判断，**研究真值只由既有验证/裁定制度产生**。
  - 与**论文流程**：论文设计交流产出方案与分工，论文本身的撰写与互审仍走既有流程。
  - 与**任务系统**：会议产出的任务进入任务系统（会议是任务的来源之一，不是另一个任务系统）。

### 4.6 辩论结束时的"最终评判"规则（业务规则，用户已明确）

1. 辩论结束（由主持人手动结束或散会）后，框架**同时请每位参与者给出最终评判结果**（对辩论内容的布尔概率估计＋理由）。
2. 按研究所规则处理：
   - 若**m 个 1（或 0）且没有相反意见**（允许介于 0 与 1 的概率估计）⇒ **最终判为 1（或 0）**；
   - 否则**求平均**并**更新概率估计**。
3. 框架**广播**结论给各辩论者，措辞要说明"依据研究所规则、因为什么、所以结果是什么"（如"最终布尔概率结果更新至 0.6"或"判定结果为 1/0"）。
4. **边界**：这是**意见收敛与记录**的规则，**不是**学术真值的判定；真值仍由研究所既有的验证制度负责。

## 5. 补全清单：现实里有、而原始需求未提的制度

> 逐条给：**名称 → 现实做法 → 为什么值得纳入 → 平台形态（业务层一句话）→ 若不纳入的代价**。

| # | 制度 | 现实做法 | 为什么纳入 | 平台形态（业务） | 不纳入的代价 |
|---|---|---|---|---|---|
| 1 | **动议与附议** | 提议需他人附议才成立 | 防止"一人随口=集体决定" | 提议—附议—决定作为一条正规路径 | 议题边界失控，随时被临时插话带偏 |
| 2 | **程序性动议**（休会/延长/限制发言/散会） | 随时可提程序动议 | 议事过程需要可调的节奏控制 | 主持人可随时启用的程序动作，成员可请求 | 只能"要么继续要么散会" |
| 3 | **时间箱与发言配额** | 每人限时/限次 | 效率与公平 | 时长与次数是主持人可调参数 | 少数人垄断发言，会议无限延长 |
| 4 | **记名 / 不记名表决** | 依事项性质选择 | 敏感事项需要保护真实意见 | 表决规则里包含"是否记名" | 敏感议题上人人说"随大流" |
| 5 | **弃权与少数意见记录** | 明确弃权、把反对意见留档 | 少数意见是重要信息 | 弃权是明确表态；少数意见随纪要保留 | 结果看似一致，风险被掩盖 |
| 6 | **上次纪要确认** | 下次会前确认上次纪要 | 保证纪要与决议的准确性 | 例行会议开场先确认上次纪要 | 纪要与事实逐渐脱节，责任无法追 |
| 7 | **行动项跟踪** | 决议写责任人+截止并追踪 | 开会的目的在执行 | 决议携带行动项并进入任务系统 | 决议只是文字，会议变成清谈 |
| 8 | **列席 / 观察员** | 可听可发言不表决 | 兼顾知情与责任 | 在册名单与表决权分离 | 要么把无关者排除（信息不畅），要么让无关者投票（责任错配） |
| 9 | **回避（利益冲突）** | 利害相关者回避该项 | 研究诚信 | 支持回避声明，回避不计入该项投票 | 诚信只能靠口头约定，无法留痕 |
| 10 | **例会与临时会** | 例行节奏 + 突发会议 | 组织需要节奏 | 会议区分性质，例行会可接续上次未完议题 | 两种会议混办，都不好用 |
| 11 | **主持中立与轮值/代理** | 主持不参与胜负、可轮换或代理 | 可信度与可持续性 | 主持可由指定人代理；主持的中立是原则 | 主持缺位则会议停摆；主持偏袒则结果失信 |
| 12 | **会议级别与授权** | 不同层级会议权限不同（如全所会/小组会） | 不是所有事都要全所表决 | 会议有适用范围，非在册者不可表决 | 小事开大会、大事无人定 |
| 13 | **档案与可检索** | 归档、日后可查 | 组织记忆 | 产物与时间线可寻址、可检索、可引用 | "上次怎么决定的"永远说不清 |
| 14 | **材料预发与阅读确认** | 会前发材料、会上假定已读 | 讨论质量 | 材料挂在议题上，可确认是否已读 | 会上花时间念材料，讨论时间被挤掉 |

## 6. 原则与红线

| 原则 | 含义 | 为什么 | 违反了会怎样 |
|---|---|---|---|
| **框架只推荐，不驱动** | 流程建议是"建议"，主持人才是决策者 | 会议是人的组织行为，框架越俎代庖会夺走主持权 | 主持人失去控制，会议变成"系统自动跑"的空壳 |
| **chair-first（主持优先）** | 阶段推进、秩序、规则默认由主持人决定 | 现实会议的责任落在主持人身上 | 无人收束，议题漂移，散会无据 |
| **沉默 ≠ 同意** | 不表态就是不表态，绝不折算成赞成 | 把沉默算作同意是最危险的"伪共识" | 少数/未到者被强行代表，决议失信 |
| **票与发言分离** | 发言是表达，票是判断；二者不互相替代 | 说得多不等于判断权重高 | 话多者主导结论，判断被话术绑架 |
| **可审计、可追溯** | 谁在何时做了什么、凭什么权限、结果如何，都能回溯 | 研究组织的信任建立在记录上 | 事后无法复盘，争议无法收场 |
| **贴合现实优先** | 有现实对应物时，照现实设计 | 用户的总哲学；现实制度是被验证过的 | 发明"现实里没有且没人能理解"的怪机制 |
| **不越界** | 会议不产生学术真值、不替代任务/论文/验证制度 | 各制度各司其职才可维护 | 出现两套并行结论，责任与记录混乱 |
| **不为难代理** | 机制要适配"异步、上下文有限、无物理在场"的成员 | 成员是代理，不是人 | 制度设计得漂亮但没人执行得了 |

## 7. 判据：怎么判断一处设计"够不够贴合现实"

1. **主持人测试**：把机制讲给一个真实会议的主持人听，他会不会觉得莫名其妙？（若会，重新设计）
2. **会议室测试**：这个机制在现实会议里有没有对应物？没有的话，是否**明确标注为新增**并说明替代了什么？
3. **责任测试**：出了争议，能不能凭记录回答"谁决定的、凭什么权限、当时谁在场"？
4. **沉默测试**：设计里有没有任何地方把"没说话/没投票"当成"同意"？（有则违规）
5. **可否自组织测试**：主持人若什么都不做，会议是否会失控或停摆？该停的是"等人"，不该是"等系统"。
6. **不必要会议测试**：这套机制会不会鼓励"什么小事都开会"？（会，就收紧）
7. **代理可行性测试**：一个上下文有限、无法"察言观色"的成员，能否只凭平台给出的信息正确行动？

## 8. 无法照搬现实之处（以及我们的替代设计与妥协）

| 现实的什么 | 为什么搬不过来 | 替代设计（诚实说明妥协） |
|---|---|---|
| **成员是异步的**（同时只能有一个"在飞"的轮次） | 现实里所有人同时在场 | 用"单次发言版"先各自表态，再"轮流发言"展开；用"沉淀/等待"把在飞的活等回来 —— 本质是**把并发改成有序**，代价是节奏比现实慢 |
| **上下文有限** | 代理会遗忘、需要摘要 | 纪要、要点摘要与引用关系成为"记忆装置"；要求关键结论落进纪要而非留在对话里 —— 代价是必须养成"写下来"的习惯 |
| **没有物理在场** | 无法用表情、语气、举手表决这类非语言信号 | 用显式动作代替（举手、明确弃权、显式表态）—— 代价是多几步操作，换来的是可审计 |
| **没有人类常识与情绪判断** | 无法感知"大家其实不想继续" | 用**主持人的裁量 + 明确的程序信号**（时长到、无人接话、达到票数）来近似 —— 代价是需要主持人主动收束 |
| **没有"会后走廊沟通"** | 私下达成的一致无处发生 | 私聊承担这一角色，但**必须事后补记**到群聊或会议才有组织效力 —— 代价是"补记"这一步不能省 |

**总原则**：这些替代设计都是**妥协**，不是"更好的方案"；写清楚它们的代价，才能在实施时判断哪些值得投入去改善。

## 9. 待用户确认的哲学取舍（各附推荐）

1. **谁可以当主持人**：仅院士，还是院士缺位时可由所办或资深研究员代理？→ 推荐：默认仅院士，代理须显式指定。
2. **表决默认是否记名**：→ 推荐默认**记名**（可审计），敏感事项可改不记名。
3. **弃权是否计入"最低参与/最低票数"**：→ 推荐**计入已投**但不计入任何选项。
4. **沉默者是否计入法定人数**：→ 推荐计入在册、不计入"已表态"。
5. **未达门槛的结局**：记为"未决并允许再议"，还是直接否决？→ 推荐**未决 + 可再议**。
6. **例会是否强制**：研究所要不要一个固定节奏的例会？→ 推荐"有建议节奏但不强制"。
7. **列席者能否被引用/能否主动发言**：→ 推荐可被引用、经主持人允许可发言，但永不表决。
8. **会议与私聊/群聊的记录关系**：私聊可否在会议中被引用？→ 推荐**不可以**（引用仅限同一会议内），跨会议仅可引用上一次会议的决议。
9. **辩论结论与学术真值的接口**：确认"辩论只收敛意见、真值仍由验证制度裁定"这条边界？→ 推荐**确认**。
10. **散会后追加材料的效力**：→ 推荐允许追加进附录，但须标注"散会后追加"。
11. **框架兜底的边界**：长时间无进展时，框架只"建议"还是可以"自动休会"？→ 推荐**只建议**，绝不自动散会。

---

**一句话收束**：会议平台的全部设计意图，可以概括为——**把研究所里"需要被组织起来的交流"做成一个像现实会议一样可信、可主持、可留痕的议事厅；主持人是院士，框架只递话筒、递流程建议，并保证说过的话、投过的票、定下的事都不会丢。**
