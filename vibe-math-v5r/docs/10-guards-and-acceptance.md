# 第 10 章 · 守卫与验收

本章是「守卫与验收」的唯一权威：把每条断言、其所在层、对应单点变异与**预期红名**列成总表，并给出真机验收判据与覆盖边界记账。

## 1. 守卫总表（断言 → 所在层 → 单点变异 → 预期红名）

> 三形态沿用同一惯例：**源码级断言 → 变异族（具名红） → 套件内自探针**。两条纪律：**每条新断言都要一条单点具名红**；**先绿后变异红**（在红的基础上再变红不算证据）。新增工作点应尽量折进既有套件，避免作业数漂移。

| 期 | 断言（源码级／行为级／E2E） | 单点变异（具名红） |
|---|---|---|
| ① | 命令目录表存在且四命令齐；权限检查**先于**开会生效；授权台账有**过期字段** | 删掉权限检查调用 ⇒ "只有院士能开会"红；令授权**永不过期** ⇒ "临时授权可回收"红 |
| ② | 行为级：单次模式**第二次发言被拒**（结构化错误码，非提示词）；E2E：轮流模式每条含引用、**悬空引用被拒** | 去掉配额判断 ⇒ "每人恰一条"红；把引用校验降级为提示词 ⇒ "悬空引用被拒"红 |
| ③ | 行为级：**沉默不计票（0 票）**；**有未投票 ⇒ 不得结题**（具名阻塞）；门槛与法定门槛函数**同源** | 把沉默当赞成票 ⇒ "沉默≠同意"红；允许带未投票结题 ⇒ "未投票阻塞"红；门槛改成常数 ⇒ 门槛同源断言红 |
| ④ | 源码级：类型字段出现在**推荐输入**与**流程选择**两处；行为级：院士**覆盖被记录**；E2E：无推荐仍收束 | 硬编码流程忽略类型 ⇒ "类型驱动"红；把推荐写成强制（覆盖被忽略）⇒ "可覆盖"红 |
| ⑤ | 行为级：m 个 1/0 无反例 ⇒ 定论；**有反例 ⇒ 平均**（两个方向各一例）；广播**含规则引用** | 去掉"无反例"判据 ⇒ 定论分支红；有反例仍下定论 ⇒ 平均分支红；广播去掉规则引用 ⇒ 广播断言红 |

## 2. 用户点名的专项断言（一条不少）

类型字段驱动机制；权限与临时授权（含回收）；引用完整性（含悬空引用被拒）；投票板门槛；聚合规则（m 个 1/0 且无反例 ⇒ 定论；否则取平均并更新概率）；**沉默≠同意**；**未投票阻塞结题**。

以上每项都必须在总表中有对应的**具名红**；缺红名的断言视为未落地。

## 3. 真机（SLV）验收判据

**硬预算模板**：配置＋状态 ≤50k tokens；v5 启动＋1 轮 ≤250k；v4 启动＋1 轮 ≤900k；双常驻会议 ≤600k；总预算 ≤2.5M。**超时或触顶一律记 NON-RESULT**（不得当作通过）。

| 类型 | 可判定判据 | 预算／墙钟建议 |
|---|---|---|
| 辩论 | ① 开局"单次群聊"**每人恰一条**（比对纪要发言者集合与在场成员集合）② 轮流辩论**每条含引用**且引用目标存在 ③ 结束时**每人给出概率估计**（纪要中每人一个 0–1 数值）④ 广播含"**根据研究所规则，由于…**"三要素 | ≤250k／≤10 min |
| 平常会议 | ① **无人举手也能顺利收束**（无超时错误）② 纪要具名记下"已获得机会、选择未发言" ③ 收束后持久 OPEN 标记被清除 | ≤250k／≤10 min |
| 表决 | ① 门槛＝法定门槛函数而非硬编码 ② **沉默不产生票**（票数＝显式投票人数）③ 有未投票者 ⇒ **结题被具名阻塞** ④ 达门槛且无反例 ⇒ 定论，否则取平均 | ≤250k／≤10 min |
| 兼容复验 | 旧状态文件（含会议开启标记）能被读入且会议续跑；旧口径的 run 不被新语义误伤 | 各 ≤100k |

## 4. 覆盖边界（如实记账）

1. **枚举点的边界**：总表按"期"给出断言与变异，但并非每条断言都穷举了其目标函数的全部分支；未被枚举的分支**不视为已覆盖**，须在追加时补红名。**（出处＝编制期实测）**
2. **探针覆盖面**：既有 `formal-sensitivity` 一类的灵敏度探针针对的是既有预设，**未覆盖本次重构的接口面**；接口面的覆盖只来自本章总表与真机判据。**（出处：本手册编制期对审计实现的实测核查，非底稿条目）**
3. **并发脆弱**：并发场景（同一议题多入口、并行会议、唤醒竞争）目前只有"互斥与单一写入口"层面的防线，**缺少压力型验证**；处置为：以互斥规则＋稳定标识＋单写入口三重防线承接，并在真机判据里以"并行会议不得就同一议题产出实体定论"作为可判定项。**（出处＝编制期实测）**
4. **未拍板项**：凡涉及政策数值（门槛、时限、授权有效期）的分支，其验收以"是否走单一权威来源"为判据，而不是以具体数值为判据；数值变动不改变本节结论。

## 5. 兼容与迁移的验收要点

- 新旧参数面必须同源：新增参数须进入参数面与冻结键集，否则键面守卫会红。
- 纪要格式向后兼容：新增分区（发言区／投票区）不改变旧纪要的读法，旧纪要不得被重写。
- 状态文件新增字段必须**可选**且缺省有合理默认；读旧文件不需要版本号口径变更。
- 一切新状态落在研究所目录树内，**绝不写工作区之外**。

## 本章验收判据

1. 总表每条断言都带"所在层＋单点变异＋预期红名"，且红名是可搜索的具名标签。
2. "用户点名的专项断言"七项齐备，且每项都能在总表中找到对应红名。
3. 真机判据四类型齐备，每条可判定、带预算；超时/触顶明确记为 NON-RESULT。
4. 覆盖边界四条如实记账，明确写出"未枚举分支不视为已覆盖"。
5. 兼容与迁移要点覆盖参数面、纪要格式、状态字段、目录边界四项。
6. 正文引用只指向本手册章节号；不含会话措辞、代理句柄、任务号或审查标签。
