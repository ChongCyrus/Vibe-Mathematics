# A 稿 · 会议平台模型（Meeting Platform — Model & Contracts）

> 设计稿（只策划）。本文只描述**模型、状态机、命令契约、权限机制、观测面与现实对照**；不含实现，不含代码、测试、文档改动。
> 术语约定：**会议（meeting）** 是平台的一等实体；**辩论、表决、论文设计交流**等不是并列实体，而是**同一平台上的不同「会议类型」任务**。
> 面向代理的文本示例（提示词片段、命令说明）一律写成**干净、自足、脱离本项目历史**的样子：读者只需本稿即可理解，不必猜。

---

## 0. 一页总览

- **一个平台**：所有"把人聚在一起交流"的机制（平常会议、学术讨论、任务规划、辩论、结题表决、论文设计交流…）都是会议；差别只在**会议类型**以及该类型下**可用命令/特色机制**。
- **主办方＝院士（chair / host）**：定题目与议程、定会议类型、开关会议、驱动阶段迁移、设发言秩序与规则、设群聊参数与投票规则。
- **框架不是主持人**：框架只做三件事 —— ① 按类型**推荐**一套默认流程（可被院士随时改写）；② 提供**特色机制**（计时、沉淀、投票板、任务板、辩论结构…）；③ 在**兜底**场景（超时、在飞成员未归、无人接话、达到硬上限）提醒或暂缓，**不替院士决定**。
- **现实优先**：命令与阶段尽量用现实会议的语言（点名、动议、附议、休会、延长、散会、纪要、决议），并在第 7 节列出"为贴合现实而新增"的东西。

## 1. 平台模型：会议是一等实体

### 1.1 实体字段（Meeting）

| 字段 | 语义 | 备注 |
|---|---|---|
| `id` | 会议标识（如 `mt-<序号>` 或 `mt-<日期>-<序号>`） | 全局唯一、不可复用 |
| `title` | 会议**题目**（一句话） | 院士填写；用于纪要标题与推送 |
| `agenda` | **议程**：有序条目列表（每条含 `text`、可选 `owner`、可选 `timebox`） | 现实会议的"议程表" |
| `type` | **会议类型**（见 1.2） | 决定框架启用哪些特色机制与默认规则 |
| `phase` | 当前**阶段**（见第 2 节状态机） | 迁移只能由合法命令触发 |
| `chair` | **主持人**（默认：院士）；可指定"联合主持" | 权限表以主持人为顶点 |
| `roster` | **在册名单**：应到成员（含身份、是否被授权发言、是否可投票） | 与全体成员名单区分：可邀请旁听 |
| `attendance` | **出席情况**：每人 `present / absent / late / left_early / excused` | 现实会议点名 |
| `permissions` | **权限表**（见第 4 节） | 默认表 + 临时授权 |
| `speech_policy` | 发言机制与参数（模式、顺序、次数上限、时长、静默名单） | 见 3.3 |
| `ballot` | 投票板（可空）：选项、规则、票、计票状态 | 见 3.6 |
| `task_board` | 会议任务板（可空）：待领/已领/已分配 | 见 3.7 |
| `artifacts` | **产物路径**：纪要、决议、投票记录、任务板快照、材料附录 | 路径规则由实现定；模型只要求"可寻址、可归档" |
| `timeline` | **事件记录**（append-only）：`{at, actor, kind, payload, receipt}` | 审计与回放的唯一依据 |
| `started_at / ended_at / duration_ms` | 时间 | 含休会累计 |
| `recess` | 休会状态：`{at, reason, expected_resume?}` | 休会≠散会 |
| `minutes` | 纪要：按议程分节、含发言摘录、决议、附件 | 见 5.4 |
| `status` | `draft / summoned / in_session / recessed / adjourned / archived` | 见第 2 节 |

### 1.2 会议类型（建议取值与语义）

> 类型只决定"**旋钮**"与默认值；具体"类型 × 旋钮"矩阵见 B 稿，本稿只列**有哪些旋钮**。

| 类型（中/英） | 语义 | 默认侧重 |
|---|---|---|
| 平常会议 `regular` | 汇总各自研究状况、同步进展、分配与组织工作 | 轮流发言 + 任务板 |
| 学术讨论 `seminar` | 围绕某个命题/方法自由讨论、互相质疑、形成共识或分歧清单 | 自由群聊 + 引用 + 可开投票板（意向性） |
| 任务规划 `planning` | 拆解任务、定优先级、分派责任人、定验收 | 群聊 + 任务板 + 分配/认领 |
| 辩论 `debate` | 就一个议题设正反方，交叉质询，最后各自总结 | 正反方结构 + 计时 + 定向质询 + 结论陈述 |
| 结题表决 `resolution_vote` | 就"是否结题/是否采纳"做正式表决并形成决议 | 点名 + 动议/附议 + 投票板（规则严格）+ 计票 + 决议 |
| 论文设计交流 `paper_design` | 定论文结构、分工、口径与图表方案 | 展示 + 逐节讨论 + 任务板（写作任务） |
| 例会/站会 `standup`（可选） | 每人极短汇报 + 阻塞项收集 | 单次发言版 + 时长硬限 |
| 临时会议 `ad_hoc`（可选） | 为解决突发阻塞临时召集 | 主持人强控 + 最短流程 |

**每种类型框架可启用的"旋钮"（仅列旋钮清单，不写组合）：**

- **发言机制**：轮流 `round_robin` / 自由群聊 `open_chat` / 单次发言 `single_round` / 举手 `hands` / 点名发言 `call_on` / 定向质询 `directed`。
- **秩序与配额**：发言顺序表、每人**发言次数上限**、每人**单次时长上限**、总时长上限、可申请**延长**。
- **群聊治理**：是否允许无限发言、每人可发条数、静默名单、主持人可否删/折叠不当发言、是否允许并行多条。
- **沉淀/等待**：是否在关键节点**等待在飞成员**落地（缓冲），等待上限与超时后的处理（继续/顺延/记缺席）。
- **投票板**：是否可开、选项数上限、单选/多选、每人最多/最少选几项、**最少收集票数**、是否记名、是否允许多轮、是否有并列处理规则、是否有弃权票。
- **辩论结构**：正反方名单、发言轮次（立论/质询/反驳/总结）、每轮时长、是否允许插话、质询是否必须被回答、总结是否限时。
- **材料与展示**：是否要求预交材料、是否允许共享屏幕式"材料条目"、讨论是否必须**引用材料条目**。
- **动议机制**：是否允许成员提动议/附议、动议是否必须附议才进入表决、动议可否被撤回。
- **纪要**：详尽度（要点/逐条摘要/全文摘录）、是否自动生成热榜、是否需要落库为决议。
- **产物**：产出纪要/决议/任务清单/材料附录中的哪些、命名与归档位置。
- **观察与提醒**：静默提醒（长时间无人发言）、超时提醒、离席提醒、是否对缺席者补发纪要。

### 1.3 与现有平台的关系（模型层面）

- 既有的"辩论录""表决（真值裁定）"在模型上都归约为**会议产物**：辩论是 `debate` 类型会议；结题表决是 `resolution_vote` 类型会议，其"布尔概率估计 + 理由"是**平台上的一个专用命令**，其**裁定语义**仍由既有的真值规则负责（平台不重复定义真值）。
- 会议**不替代**任务系统：会议期间产生的任务应落到任务板（与全局任务 DAG 的关系见"待拍板清单"第 5 条）。

## 2. 状态机（chair 驱动，framework 只推荐与兜底）

```
draft(筹备)
  │ 召集 convene
  ▼
summoned(已召集) ──取消 cancel──▶ adjourned(散会·未开成)
  │ 开场 open_meeting（点名 roll_call 可在此之前/之后）
  ▼
in_session(进行中) ──休会 recess──▶ recessed(休会) ──复会 resume──▶ in_session
  │        ▲                              │
  │        └──────── 解散/超时散会 ────────┘
  │
  │  子阶段（在 in_session 内迁移）
  ├─ roll_call(点名)
  ├─ opening(开场·重申题目与议程)
  ├─ speech(发言)  ── 模式：round_robin / open_chat / single_round / hands / call_on / directed
  ├─ discussion(自由讨论)  （含引用、追问）
  ├─ settling(沉淀·等待在飞成员落地)
  ├─ motion(动议/附议)
  ├─ debate(辩论)  ── 立论 → 质询 → 反驳 → 总结
  ├─ voting(投票)  ── 投票板开放
  ├─ tally(计票)
  ├─ resolution(决议/结论归纳)
  └─ minutes(纪要确认)
  │ 散会 adjourn
  ▼
adjourned(散会) ──归档 archive──▶ archived(归档)
```

**合法迁移（谁可触发）**

| 迁移 | 触发命令（默认权限） | 说明 |
|---|---|---|
| `draft → summoned` | 召集 `convene`（院士） | 必须已写 `title` 与 `agenda`（至少 1 条） |
| `summoned → in_session` | 开场 `open_meeting`（院士） | 可先 `roll_call` 点名；缺人不停会，记 `absent` |
| `in_session: 任意 → speech` | 进入发言 `enter_speech`（院士）/ 由邀请发言、点名发言隐式进入 | 框架可**推荐**按议程顺序进入 |
| `speech → discussion` | 转入讨论 `open_discussion`（院士） | 讨论阶段允许自由发言（受群聊参数约束） |
| `discussion → settling` | 沉淀 `wait_for_settle`（院士） | 等在飞成员落地；超时后按院士设置继续或顺延 |
| `任意 → motion` | 提出动议 `motion`（成员，需允许）/ 附议 `second`（成员） | 有"需附议"规则时，达附议阈值才可进入表决 |
| `motion → voting` | 进入表决 `open_ballot`（院士） | 投票板必须已建或在此时创建 |
| `voting → tally` | 截止投票 `close_ballot`（院士）或达票数/时长自动截止（兜底） | 自动截止属**兜底**，须写事件 |
| `tally → resolution` | 宣布结果 `announce_result`（院士） | 结果可"通过/否决/未达最低票数/并列" |
| `resolution → minutes` | 生成纪要 `draft_minutes`（院士或指定纪要人） | 纪要与决议一并落库 |
| `minutes → adjourned` | 散会 `adjourn`（院士） | 未归档也可散会；产物保留 |
| `任意 → recessed / recessed → in_session` | 休会 `recess` / 复会 `resume_meeting`（院士） | 休会时长计入会议时间 |
| `任意 → adjourned` | 散会（院士）；**框架兜底**：达到硬上限或长时间无活动且无人接话时**建议**散会 | 框架不得自行散会 |

**迁移原则**
1. **chair-first**：所有迁移默认由院士命令触发；框架只在"推荐下一步"和"兜底"介入。
2. **推荐即建议**：框架给出"建议进行下一步：进入表决"，院士可无视、可改顺序、可插入休会或延长。
3. **每次迁移都写事件**（`timeline`），事件含 `actor` 与 `receipt`；纪要与审计都读事件流。
4. **同一阶段可重入**：如 `discussion → speech → discussion` 允许多次；`voting` 允许多轮（若类型允许）。
5. **不可逆动作可逆化**：散会后如需继续，只能**新开一次会议**（保留原会议为历史），避免"散会后偷偷继续"。

## 3. 命令目录（完整契约）

**统一字段**：`名字（中/英）`｜**语义**｜**参数**｜**内容字段**（是否必须携带正文）｜**返回与回执**｜**对会议状态的影响**｜**默认权限**｜**可临时授予**。

> 约定：`会议上下文` 指当前会议；`@成员` 指在册成员 id；"回执"指调用返回中可被引用、可进事件流的结构化结果（含 `event_id`）。

### 3.1 院士（主持人 / 主办方）命令

| 命令（中/英） | 语义 | 参数 | 内容字段 | 返回与回执 | 对状态的影响 | 默认权限 | 可临时授予 |
|---|---|---|---|---|---|---|---|
| 召集会议 `convene` | 开会：定题目与议程 | `title`, `agenda[]`, `type`, `roster?` | 否（题目/议程即内容） | `meeting_id` + 事件 | `draft→summoned` | 院士 | 所办（如用户要求） |
| 设定议题 `set_agenda` | 改写议程（增删改条目） | `agenda[]` | 是（条目文本） | 新议程快照 | 原地修改 | 院士 | 联合主持 |
| 设定会议类型 `set_meeting_type` | 指定类型 ⇒ 决定启用哪些机制 | `type` | 否 | 生效的机制清单 | 原地修改（进行中可改：需记事件） | 院士 | 无 |
| 点名 `roll_call` | 逐人确认是否在场 | `roster?` | 否 | 出席表 | 进入/重申 `roll_call`；更新 `attendance` | 院士 | 纪要人 |
| 开场 `open_meeting` | 重申题目、议程与规则，宣布开始 | `note?` | 可选 | 开场记录 | `summoned→in_session`（首个阶段通常是 `opening`） | 院士 | 无 |
| 邀请发言 `invite_speech` | **邀请＝"邀请内容 + 邀请"一体**：给某成员一条带正文的邀请 | `to`(@成员), `content`(邀请正文), `expect?`(希望对方谈什么), `timebox?` | **是**（`content` 必填） | 邀请回执 + 被邀者通知 | 进入 `speech`（若尚未进入），把该成员列入发言队列 | 院士 | 联合主持 |
| 设定发言顺序 `set_speaking_order` | 指定谁先谁后 | `order[@成员]` | 否 | 顺序快照 | 修改 `speech_policy.order` | 院士 | 联合主持 |
| 点名发言 `call_on` | 按顺序请下一位发言（默认自然顺序） | `next?`(@成员；缺省=按顺序取下一位) | 可选（可附"请围绕…谈"） | 点名回执 | 进入 `speech` 的 `call_on` 模式；记录本次机会 | 院士 | 联合主持/纪要人 |
| 切换发言机制 `set_speech_mode` | 在轮流/群聊/单次/举手/点名/定向之间切换 | `mode`, `policy?`(次数/时长/静默) | 否 | 生效策略 | 修改 `speech_policy` | 院士 | 无（机制级） |
| 群聊参数 `set_chat_policy` | **院士当群管**：设每人可发条数、是否禁言、是否允许并行 | `per_member_quota?`, `mute[@成员]?`, `unmute[@成员]?`, `allow_parallel?` | 否 | 策略快照 | 修改 `speech_policy.chat` | 院士 | 联合主持 |
| 单次发言轮 `single_statement_round` | 每人**仅一次**发言：先各自把话说完，再进入讨论 | `roster?`, `timebox?` | 否 | 轮次清单与进度 | 进入 `speech(single_round)` | 院士 | 无 |
| 举手管理 `manage_hands` | 允许/暂停举手；给某人优先发言 | `allow?`, `prioritize?`(@成员), `clear?` | 否 | 举手队列 | 进入 `speech(hands)`；维护举手队列 | 院士 | 联合主持 |
| 静默/解除静默 `mute / unmute` | 单人静默（不许发言，仍可听） | `who`(@成员), `reason?` | 否 | 静默名单 | 修改策略 | 院士 | 联合主持 |
| 沉淀/等待 `wait_for_settle` | **缓冲**：等在飞成员把手上的活跑完、决策落定 | `cap_ms?`, `on_timeout?`(`continue`/`defer`/`absent`) | 否 | 等待清单与结果 | 进入 `settling`；超时按设置继续 | 院士 | 联合主持 |
| 休会 `recess` | 暂时中止，保留会议与产物 | `reason?`, `expected_resume?` | 可选 | 休会记录 | `in_session→recessed` | 院士 | 联合主持 |
| 复会 `resume_meeting` | 恢复 | — | 否 | 复会记录 | `recessed→in_session` | 院士 | 联合主持 |
| 延长 `extend` | 延长时长或延后截止 | `target`(`speech`/`ballot`/`meeting`), `by_ms` | 否 | 新截止 | 修改计时参数 | 院士 | 联合主持 |
| 动议 `motion` | 提出动议（议题/程序/决议） | `kind`, `text` | **是** | 动议记录 | 进入/保持 `motion` | 院士（成员需授权） | 见 4.4 |
| 进入表决 `open_ballot` | 打开投票板（或先创建） | `ballot_id?`, `question`, `options[]`, `rules` | **是**（问题与选项） | 投票板 id | `→voting` | 院士 | 联合主持 |
| 创办投票板 `create_ballot` | 设选项内容与规则 | `question`, `options[]`, `mode`(`single`/`multi`), `max_choices?`, `min_choices?`, `min_votes?`, `secret?`, `rounds?`, `tie_rule?`, `deadline?` | **是** | 投票板快照 | 创建 `ballot`（不自动进入 `voting`） | 院士 | 无 |
| 截止投票 `close_ballot` | 结束收票 | `ballot_id?` | 否 | 计票前状态 | `voting→tally` | 院士 | 联合主持 |
| 计票 `tally` | 统计并给出结果判定（含并列/未达最低票数） | `ballot_id?`, `rule?` | 否 | 计票表 + 判定 | `voting→tally`（若从 `tally` 调用则重算） | 院士 | 纪要人 |
| 宣布结果 `announce_result` | 宣布通过/否决/未达最低票数 | `text?` | 可选 | 结果回执 | `tally→resolution` | 院士 | 联合主持 |
| 记录决议 `record_resolution` | 把结论写成**决议**（可含责任人/期限） | `text`, `actions[]?` | **是** | 决议 id | `resolution` 内落库 | 院士 | 纪要人 |
| 生成纪要 `draft_minutes` | 依事件流与议程生成纪要 | `detail?`(`brief`/`normal`/`full`) | 否 | 纪要草稿 | `→minutes` | 院士 | 纪要人 |
| 指定纪要人 `appoint_secretary` | 指定谁写纪要 | `who`(@成员) | 否 | 授权记录 | 修改权限表 | 院士 | 无 |
| 创办任务板 `create_task_board` | **创办待领任务/任务板**：把会议产物变成可认领的任务清单（待领任务可被成员请求认领） | `tasks[]`(题目/描述/验收/优先级) | **是** | 任务板快照 | 创建 `task_board` | 院士 | 联合主持 |
| 分配任务 `assign_task` | 把某任务**直接派给**某人 | `task_id`, `to`(@成员), `why?`, `due?` | 可选 | 派单回执 | 更新任务板（`assigned`） | 院士 | 联合主持 |
| 撤回/撤销 `revoke` | 撤回动议/邀请/任务/授权 | `target_kind`, `target_id`, `reason` | 是（理由） | 撤回记录 | 依对象而定，均写事件 | 院士 | 无 |
| 散会 `adjourn` | 结束会议（产物保留） | `note?`, `archive?` | 可选 | 散会记录 + 产物路径 | `→adjourned`（可选 `→archived`） | 院士 | 无 |

### 3.2 成员命令

| 命令（中/英） | 语义 | 参数 | 内容字段 | 返回与回执 | 对状态的影响 | 默认权限 | 可临时授予 |
|---|---|---|---|---|---|---|---|
| 举手发言 `request_floor` | 请求发言机会（排队） | `about?` | 可选 | 举手回执 + 队列位置 | 进举手队列（不改阶段） | 在册成员 | — |
| 发言 `speak` | 实际发言（群聊或轮到本人时） | `text`, `quote?` | **是** | 发言 id + 事件 | 记录发言；可能推进"每人次数" | 在册成员（受策略约束） | — |
| 引用发言 `quote_speech` | 发言时引用过去某条发言（见第 5 节） | `ref`(发言 id), `excerpt?`, `visibility?` | 是（正文另附） | 引用关系回执 | 记录引用；通知被引用者 | 在册成员 | — |
| 定向质询 `challenge` | 辩论中向对方/某人提一个必须回答的问题 | `to`(@成员), `text`, `timebox?` | **是** | 质询记录 | 在 `debate(directed)` 内排队 | 辩论参与方 | 见 4.4 |
| 回答质询 `answer_challenge` | 回应质询 | `challenge_id`, `text` | **是** | 回答记录 | 关闭该质询（或标记待答） | 被质询者 | — |
| 投票 `cast_ballot` | 在投票板投票 | `ballot_id`, `choices[]`, `weight?` | 可选（理由） | 投票回执（是否保密依规则） | 记票；达阈值可触发兜底截止 | 有投票权者 | — |
| 弃权 `abstain` | 明确弃权（计入"已投"但不计入选项） | `ballot_id`, `reason?` | 可选 | 弃权回执 | 记弃权 | 有投票权者 | — |
| 附议 `second` | 附议某动议（使动议成立） | `motion_id` | 否 | 附议回执 | `motion` 计数 +1 | 在册成员 | — |
| 提交材料 `submit_material` | 把材料挂到议程条目/议题上 | `agenda_item?`, `kind`, `text|path` | **是** | 材料 id | 材料列表更新 | 在册成员 | — |
| 请求认领任务 `claim_task` | **请求**认领（可能需批准） | `task_id`, `plan?` | 可选 | 认领回执（`pending`/`granted`） | 任务板 `claim_pending` | 在册成员 | — |
| 请求休会/延长 `request_recess_or_extension` | 提议休会或延长 | `kind`, `by_ms?`, `reason` | 是（理由） | 请求回执 | 进入请求队列（不自动迁移） | 在册成员 | — |
| 请假/离席 `leave_of_absence` | 通报缺席或提前离席 | `until?`, `reason?` | 可选 | 出席表更新 | `attendance` 更新 | 在册成员 | — |

### 3.3 发言机制（`speech_policy` 的模式与参数）

| 模式（中/英） | 谁说话 | 关键参数 | 典型用途 |
|---|---|---|---|
| 轮流 `round_robin` | 按顺序表依次 | `order`, `per_member_limit`, `timebox` | 平常会议、站会 |
| 自由群聊 `open_chat` | 任何在册成员 | `per_member_quota`, `mute[]`, `allow_parallel` | 学术讨论、头脑风暴 |
| 单次发言 `single_round` | 每人一次，发完即静默 | `roster`, `timebox` | 开场陈述、初始意见收集 |
| 举手 `hands` | 举手者按队列 | `queue`, `prioritize[]` | 讨论秩序化 |
| 点名发言 `call_on` | 主持人点谁谁说 | `next`, `timebox` | 严格控场、结题表决前的意见征询 |
| 定向质询 `directed` | 质询—回答成对 | `pairs`, `rounds`, `timebox` | 辩论 |

> **邀请发言与点名发言的区别**：`invite_speech` 是**带正文的邀请**（"请你谈 X，背景是 Y"），可以发给未在场者；`call_on` 是**按秩序点人**（可附一句题目提示）。两者都**不是裸动作**：都携带可审计的文字内容。

### 3.4 权限模型（机制）

**基本表示**：权限 = `(command, scope)` 的允许集合；`scope` ∈ `{meeting, phase, person}`。

- 默认表：`3.1`/`3.2` 的"默认权限"列。
- **临时授权**（append-only）：

```
grant { id, by, to, command, scope: {phase?|person?}, at, expires_at?, expires_on?, reason }
revoke { id, by, to, command, at, reason }
```

- **失效条件**：`expires_at`（绝对时间）/ `expires_on`（事件：如"投票结束即失效"）/ 显式 `revoke` / 会议散会。
- **审计要求**：每次授权与撤回都写 `timeline` 事件（含 `by`、`to`、`command`、`scope`、原因、失效条件），并在 `status/report` 的权限视图可见；**代行者必须能在事件流里回溯"当时凭什么权限做了这件事"**。
- **同命令不同场合不同权限**：权限判定 = 默认表 ∩ 阶段允许 ∩ 临时授权 − 静默/撤回。例：`motion` 在 `planning`/`debate` 允许成员使用，在 `voting` 阶段只允许主持人；`cast_ballot` 在 `voting` 之外一律拒绝。
- **可临时授予的对象**（示例，矩阵见 B）：
  - `motion` / `second` → 在册成员（`debate`、`planning`）
  - `challenge` → 辩论参与方
  - `tally` / `draft_minutes` → 指定纪要人
  - `assign_task` → 联合主持
  - `convene` → 所办（仅当用户在无院士场景下要求）

## 4. 引用的发言（Quote / 像 @ 某条消息）

**字段表示**（挂在一条发言上）：

```
quote: {
  ref: <发言 id>,            // 必须存在且可见
  excerpt: <不超过 N 字的摘录>, // 可选；缺省由系统截取
  visibility: 'meeting' | 'roster' | 'chair_only',
  notify: true | false       // 缺省 true
}
```

- **可见性**：被引用内容超出可见范围时，引用本身仍可见，但 `excerpt` 置空并标注"（原发言不可见）"，避免借引用泄漏。
- **通知语义**：被引用者收到**一次**通知（同一会议内对同一发言的多次引用合并计数，防刷屏）；**自己引用自己**不通知；`notify:false` 用于纯归档式引用。
- **纪要与热榜**：
  - 纪要：在发言摘录下以缩进形式呈现 `↳ 引用 @作者「excerpt」`，并给出原发言在时间线中的位置。
  - 热榜/摘要：把"被引用次数"作为**信号之一**（不等于质量，仅作提示）；同一段讨论里连续互相引用不计多轮。
  - 争议标记：对同一发言的引用既有"支持"也有"反对"时，摘要里并列呈现，不做裁决。

## 5. 观测面（写清"应暴露什么"，不写实现）

### 5.1 主持人（院士）视图

| 面 | 应暴露 |
|---|---|
| 会议 | `id / title / type / phase / chair / started_at / duration（含休会） / status` |
| 议程 | 条目、当前条目、每条是否已讨论、材料数 |
| 在册与出席 | 每人 `present/absent/late/left_early/excused`、身份、是否可投票、是否被静默 |
| 发言 | 当前模式与参数、发言顺序、**已获机会名单与次数**、举手队列、正在发言者、剩余时长 |
| 投票板 | 问题、选项、规则（单选/多选、上下限、最少收集票、是否记名、轮次）、已投名单（记名时）、票数、是否达最低票数、并列情况 |
| 任务板 | 待领/认领中/已分配/已完成、责任人、验收、期限 |
| 动议 | 待附议/已成立/已撤回、表决状态 |
| 事件 | 时间线（可按 kind 过滤）：谁在何时做了什么、回执 id |
| 权限 | 默认表、生效中的临时授权（谁授给谁、何时失效）、被拒命令的尝试（可审计） |
| 产物 | 纪要/决议/投票记录/任务板快照/材料附录的可寻址路径 |
| 兜底提示 | 框架的"建议下一步"（如"建议进入表决"）、超时提醒、无人接话提醒、在飞未归清单 |

### 5.2 成员视图

`phase / 当前议程条目 / 本人是否已获机会与剩余次数 / 举手队列位置 / 投票板（可否投、已投否、剩余时间）/ 任务板（可认领项）/ 本人被引用与提及 / 材料清单 / 本人可用的命令清单（随阶段与授权变化）`。

### 5.3 对外接口（`status` / `report` / `overview`）应暴露的字段

- `status`：会议概要（`id/title/type/phase/status/chair`）、当前阶段与参数、举手队列长度、当前发言者、投票板是否开放、任务板计数、**本人可用命令**、兜底提示。
- `report`：人类可读的**会议纪要式**汇报 —— 议程完成度、发言要点、决议、任务分派、投票结果（含未达最低票数/并列）、待办与阻塞。
- `overview`：跨会议的**清单视图** —— 进行中/休会/已散会、各会议类型与产物路径、全局任务板摘要。
- 三者都必须能回答："**我现在能不能做某个动作**"（权限与阶段），并给出**拒绝原因**（阶段不允许 / 权限不足 / 参数不合法）。

### 5.4 纪要（Minutes）结构

`标题（会议题目 + 时间） → 出席与缺席 → 议程逐条（讨论要点、材料、引用关系） → 动议与表决（问题/选项/规则/计票/结果） → 决议（含责任人/期限） → 任务清单 → 附录（材料、原始投票记录路径）`。

## 7. 待用户拍板清单（语义与默认值）

1. **主持人不唯一**？院士缺席时，是否允许所办/联合主持代行 `convene/adjourn`？默认值建议：不允许；由用户显式指令授权。
2. **投票默认是否记名**？建议默认**记名**（可审计），`secret:true` 时匿名但保留计票记录。
3. **弃权是否计入"最少收集票数"**？建议**计入已投**（不影响选项计数）。
4. **动议是否必须附议**？建议默认"程序动议需 1 人附议；决议动议需 2 人"（可按类型改）。
5. **会议任务板与全局任务系统是否同一张板**？建议**同一张板 + 会议来源标记**；若分开，需要明确合并规则。
6. **辩论与结题表决是否必须是两次独立会议**？建议可以"一次会议内先 `debate` 后 `voting`"，但产物分开归档。
7. **结题表决的布尔概率估计与真值裁定**：平台负责收集与计票，真值规则仍由既有裁定逻辑负责 —— 是否确认这条边界？
8. **引用能否跨会议**？建议**不能**（只能引用本次会议内的发言）；跨会议仅允许"引用上次会议的决议"。
9. **时长默认值**：发言单次上限、整场上限、投票截止时长各自默认多少？（建议：发言 5 分钟 / 整场 60 分钟 / 投票 10 分钟，均可改）
10. **未达最低票数的处理**：是记"未决"并允许再开一轮，还是直接记"否决"？建议默认**未决 + 可再开一轮**。
11. **静默成员是否仍计入在册与法定人数**？（建议仍计入在册，但不计入"已发言"）
12. **散会后是否允许追加材料**？建议允许追加到附录，但需写入事件并标注"散会后追加"。
13. **框架兜底的上限值**：长时间无活动（如 10 分钟）且无人接话时，框架只"建议散会"还是可"自动休会"？建议只建议。
