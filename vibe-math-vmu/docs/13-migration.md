> 目标：**有路可走、有据可比、有法可退**。

## 1. 迁移的三种意图（先分清）

| 意图 | 适用 | 做法 |
|---|---|---|
| **A. 复现历史行为** | 想继续按 v5r/v3 的方式跑 | 装 **v5r-pack/v3-pack**，不改内核（D4） |
| **B. 改机制** | 想调整某些规则 | 从 A 出发，改 settings/中间件（**不动内核**，R1） |
| **C. 复用历史资产** | 只想用某些已有组件 | 经 **别名层**＋已抽出的纯件（数学模块、纯算法）复用（10-§5.2） |

---

## 2. 迁移总流程（可执行）

```
① 基线：在现线（v5r/v5）跑一遍基准场景 ⇒ 存下"可观测行为基线"
② 并行：装 vmu + 目标 pack ⇒ 跑同一批场景
③ 对照：生成差异报告（§3 的观测项）
④ 分类：等价 / 有意改进 / 缺陷 / 未覆盖   ⇒（D8）**逐条报裁**
⑤ 收敛：等价项通过；改进项写进 pack README；缺陷项修 pack 或内核能力
⑥ 切换：一次性切换预设；保留旧线作为"发布缓冲"（D4）
⑦ 回退：随时切回旧预设（数据层见 §5）
```

---

## 3. 对照观测项（只看可观测行为，不看实现）

| 观测项 | 采集方式 | 等价判据 |
|---|---|---|
| 工具回执 | 同名场景调同名工具 | `ok/code/message 关键字段`一致（措辞差异记"改进/差异"） |
| 状态面 | `status()` 关键字段 | 阶段/成员/会议/表决/预算/待续**语义**一致 |
| 归档产物 | 文件与关键行 | 路径、结构、指纹一致（新增分轨/计数属**改进**） |
| 提示词 | 逐字快照 | **关键段存在与顺序**一致（措辞可差异，须记录） |
| 拒绝行为 | 负例场景 | **被拒条件与具名原因**一致（不得"以前拒现在放"） |
| 资源行为 | 预算/上限场景 | **机器强制点**一致（超限必拒且不执行） |

**差异报告格式（提案）**
`{ 场景, 观测项, 旧线值, vmu 值, 分类, 影响面, 建议 }` —— 存为 `_oneoff/vmu/parity/<pack>.md`（**逐条可追**）。

## 4. 命名与接口兼容（D6）

| 旧 | 新 | 兼容手段 |
|---|---|---|
| 工具 `vibe_v5_*` | `vibe_vmu_*` | **pack 别名层**：声明映射表 ⇒ 旧提示词/旧语料可继续调用 |
| 服务/耐久键 | `vmu.*` / 公开键清单（03-§6） | pack 提供**只读投影**（旧字段名 → 新字段） |
| 环境变量（如 `V5_PLUGIN`/`V5_SCENARIO`/`V5_TEX_ROOTS_SANDBOX`） | vmu 自有变量 | 测试侧保留**兼容读取**（旧名亦可），但文档只写新名 |
| 错误码 `V5_*` | `VMU_*` | 别名表映射；**新增语义必须用新码** |

**纪律**：别名层是**过渡**，必须标注**弃用期**与**移除条件**（否则永久背历史 ✗）。

## 5. 数据迁移与回退

- **vmu 自有耐久层**：与旧线的 `State/*.v5state.json` **不同文件**（不共享、不互改）⇒ 迁移＝**读取旧状态 → 生成 vmu 投影**（一次性工具）；
- **可迁移**：成员/编制、记录与卡片（含指纹）、决议/纪要/形式化归档、任务台账；
- **不可/不必迁移**：旧线的内部标记（如私有 retry 计数）、提示词残留缓存；
- **回退**：切回旧预设即可；**迁移工具只读旧线**，绝不改写旧线数据（✗ 保证可回退）；
- **备份**：迁移前自动备份（07-§2 同规则）。

## 6. 仓库级接入（把 vmu 装进本仓）

> 依据 B′ 侦察（**7 处接线** ＋ README 缺口 ✗）。**顺序**：

1. `vibe-math-vmu/`（含 `preset.yml`、`agent.cordis.yml`、`vibe-math-vmu.js`、`docs/`）；
2. `scripts/build-preset-rows.mjs`：`VERSIONS`/`ORDER` 各加一项 ⇒ **重生成** `cordis.patch.yml`（勿手改 ✗）；
3. `package.json`：`exports` ＋ `files[]`（含 docs）＋ `dsh.compatNote/testedVersion` ＋ **三处 DSH 区间同步** ＋ **bump `version`**（否则老用户不刷新 ✗）；
4. `installer.js`：`PRESETS` 增一条（`src`/`dst`/`files[]` 与 3 一致）；
5. 测试接线：`audit-preset-rows`（`VERSIONS`/`IDS`）、`audit-math-computation-parity`（若有数学模块，副本**字节一致**）、`audit-math-computation-contract`、`audit-persona-sensitivity`、`audit-fuzz-helpers`；
6. **README.md/README.en.md**（**当前连 v5r 都漏了** ✗ ⇒ vmu 必须写：预设清单/安装/选 pack）＋ 跑 `node scripts/update-doc-counts.mjs`（整行重写 4 处计数）＋ `audit-readme-counts` 守卫；
7. 语料：若要独立语料 ⇒ 新增 `prompt-corpus-vmu/` 并入 `files[]`；若复用 ⇒ 在测试里**显式声明**（照 v5r 复用 `V5_CORPUS_DIR` 的做法）；
8. 验收：`--counts` ＋ `GATE_RELEASE=1` 全量 ＋ `update-doc-counts --check`。

## 8. 门禁（本篇验收判据）

1. **对照可复跑**：`⑦` 全流程脚本化，一条命令产出差异报告；
2. **差异分类完整**：报告里没有未分类项；
3. **别名层可弃用**：别名可被显式关闭，关闭后旧调用**具名失败**（证明它只是过渡）；
4. **旧线零改写**：迁移工具对旧数据**只读**（文件哈希前后一致）；
5. **回退可用**：切回旧预设后旧线仍可运行且数据未变；
6. **接线无漏**：按 §6 在干净检出上装出 vmu 预设并通过 `--counts` 与文档计数门禁（含 README ✗ 这一最易漏项）。
