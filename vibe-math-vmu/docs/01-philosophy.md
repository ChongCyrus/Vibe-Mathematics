# vmu 01 · 哲学、要求与裁决记录

> 状态：**草案 v0.1**（待与 00/01/02 三份侦察合并、并与用户逐条裁定后升为 v1.0）
> 上位：本文件是 vmu 一切设计与实现的**判据来源**。任何设计若与本文件冲突，**以本文件为准**，或先改本文件（走裁决流程）。

---

## 1. 一句话

**vmu 是一个 agent preset，但它的本体是"框架"**：它只提供**能力**与**挂点**，把"运行机制"留给使用者的 **settings ＋ 中间件** 去定义。

> 实际运行机制 ＝ **vmu 框架 ＋ settings ＋ 中间件（＋ 代理自组织）**（必要时 ＋ 特殊脚本/协议，甚至额外 DSH 插件/mod）

## 2. 理念 → 工程要求（R1..R15，皆可验收）

| 编号 | 要求（Must） | 验收判据（如何证明做到了） |
|---|---|---|
| **R1 内核零策略** | 内核**不得**内置任何"某一代/某一机构形态"的机制决定；角色、规则、阈值、流程都属于上层 | 静态门：内核源码中**不得出现**代际/角色/机制专名（如 `v5r`、`学术院`、`院士`、`辩论期`…）；出现即红 |
| **R2 能力与挂点齐备** | 学术研究/数学、会议、工作流、控制流、归档、计算 六域的**能力面**与**钩子面**都要有 | 接口清单逐条可核；每域至少 1 个场景证明"能力可用"与"钩子可挂" |
| **R3 四可** | 每个影响行为的量：**可声明**（schema）、**可读**（`status`/报告）、**可改**（热改，不重启）、**可审计**（谁/何时/旧值/新值） | 每个参数有 schema 条目 ＋ 回显断言 ＋ 热改场景 ＋ 审计留痕断言 |
| **R4 设置单一源** | 参数/默认值/域检查/文档/门禁**同源**（一处声明，处处派生） | 静态门：未声明的键被读取即红；参数文档由 schema 生成且与实现一致 |
| **R5 中间件四形态** | **声明式规则**、**代码模块**、**脚本/工作流**、**外部插件** 四形态齐备且共用同一份"中间件清单" | 四形态各 ≥1 个可运行示例 ＋ 各 ≥1 个反向变异族（禁用后行为回到基线） |
| **R6 钩子契约化** | 每个钩子必须文档化：签名/时机/可否阻断/可否改写/作用域/失败语义/示例 | 文档即门禁：钩子清单与注册面**逐条对齐**，缺文档即红 |
| **R7 稳定内部接口** | 上层与插件只经**公开接口**触达内核；接口有版本号与废弃策略 | 公开接口清单 ＋ 版本化断言；内核私有符号不得被上层引用（静态门） |
| **R8 提示词可管理** | 提示词是**一等公民**：分段注册、按角色/阶段/任务绑定、可覆盖、可版本化、可快照 | 语料快照逐字对比；覆盖生效与回退各有场景 |
| **R9 归档与记忆** | 记录/卡片/分轨/指纹/头部列表/按 id 展开是**内核能力**（不是某代策略） | 归档面契约测试 ＋ 截断计数断言 ＋ 悬空 id 具名拒 |
| **R10 耐久可信** | 单一 fold 投影 ＋ 白名单 ＋ 版本迁移 ＋ 崩溃恢复；**不得**依赖宿主会话日志承载自有状态 | 恢复场景（杀进程/异常收尾）＋ 迁移场景 ＋ 日志不被污染断言 |
| **R11 可观测** | 任何机制性状态都能从**一个只读面**看清（谁在做什么、为什么被拒、当前设置何值何来） | `status()`/报告的字段表 ＋ "被拒必带具名原因"断言 |
| **R12 可复现** | 同输入同输出（除显式随机处）；时间/随机源可注入 | 重放场景：同 seed 两次结果一致 |
| **R13 门禁即文档** | 每条要求都有**具名红**的门/场景/族；文档与代码不一致即红 | 门禁清单与 R1..R15 双向映射表 |
| **R14 无屎山** | 模块化：单文件规模上限、跨模块只走公开接口、无隐式全局、无死代码 | 静态门（文件行数上限、跨模块 import 白名单）＋ 评审 |
| **R15 可迁移** | 历史资产（v5r 等）可作为**整合包**复现；迁移路径与差异有文档 | v5r-pack 行为包含对照（差异逐条报裁） |

## 3. 非目标（明确不做的）

1. **不做"又一版 v5"**：vmu 不内置某一代机制；代际差异一律进 pack（R1）。
2. **不追求"一切都可配"**：配置爆炸是反模式 ⇒ **能力面**丰富，但**默认路径**必须有一条清晰主线（"零配置也能跑"）。
3. **不替代 DSH**：vmu 是 DSH 之上的预设/插件；**不重写** DSH 的会话/工具/模型循环（除非 DSH 缺口必须自补，且要显式记录理由）。
4. **不做 GUI 优先**：GUI 面板是可选扩展（受 Client 面未核影响）；**首个交付不依赖 GUI**。
5. **不做向后兼容的枷锁**：允许破坏性重构；旧行为通过 pack/别名层复现，而**不是**让内核背历史。

## 3.1 从 v5r 继承的三条**跨域不变量**（B′ 判决：方法继承、内容重写 ✓）

> 这三条**与数学/代际无关**，是组织与判定的普适约束 ⇒ **vmu 作为一等约束继承**。

| # | 不变量 | 含义 | 违规后果（为何是红线） | vmu 落点 |
|---|---|---|---|---|
| **I-1** | **过程判定 ≠ 结束裁定**（v5r 的 R10） | "过程票数/过程统计"绝不可直接当作"裁定结论"；两者必须分离且各自留痕 | 过程数据一旦能裁定，就等于**用噪声做决策**；本仓历史上已因此出过门禁红 | 08 号表决原语（`ballot.tally` 判定点）＋ 11-§2 门禁 |
| **I-2** | **使能而非驱动** | 类型/字段/标记**只能"使能"某种可能，不能"驱动"流程**；流程由显式机制（中间件/pack）驱动 | 隐式驱动＝**不可见的行为改变**（使用者无法预测、无法审计） | 04（设置只放"量"）＋ 08（原语不隐式推进） |
| **I-3** | **两类时间不得混用** | "框架级时间"（由框架设置、用于判定）与"业务时间"（用户/内容提及的时间）严格分离 | 混用会破坏**可复现性**与**追溯性**（R12） | 01-R12 ＋ 04（**拒绝用户传入任何 `…At/…Ms`**）＋ 07（审计时间一律框架铸） |

> **未核项**：见 14-§2（U1–U7，DSH 侧事实的未核登记）。

## 7. 术语表（草案）

| 术语 | 含义 |
|---|---|
| **内核 / Framework** | L1：只提供能力与挂点，零策略 |
| **设置 / Settings** | L2：schema 单一源驱动的可声明·可读·可改·可审计参数 |
| **中间件 / Middleware** | L3：四形态的机制定义手段 |
| **整合包 / Pack** | L4：一份完整"运行机制"的声明组合（settings＋中间件＋提示词包＋可选脚本） |
| **能力面 / Capability** | 内核提供的服务与工具（做得到什么） |
| **挂点 / Hook** | 可被中间件接管的时机（在哪介入） |
| **原语 / Primitive** | 会议、表决、任务、阶段等最小可组合机制单元（内核提供，规则由上层定） |
