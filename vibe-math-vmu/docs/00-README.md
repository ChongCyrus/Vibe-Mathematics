## 1. vmu 是什么 / 不是什么

**是**：
- 一个 **DSH agent preset**（id `vibe-math-vmu`），但**本体是框架**；
- **能力与挂点的集合**：学术/数学、会议、工作流、控制流、归档、计算 六域的基础设施、接口、可调控参数；
- **一套定义"运行机制"的手段**：**settings ＋ 中间件（四形态）＋ 整合包(pack)**；
- **一批可直接用的整合包**：用 settings/中间件/提示词包复现 v5r、v3 等运行模式。

**不是**：
- ❌ 不是"又一版 v5/v5r"——内核里**没有**任何一代的机制决定（见 01-R1）；
- ❌ 不是"什么都能配"的配置地狱——**零配置也能跑**，主线清晰；
- ❌ 不是 DSH 的替代品——vmu 建在 DSH 之上，缺口自补须显式记录理由（见 01-§3）；
- ❌ 不是 GUI 优先项目——面板是可选扩展，首个交付不依赖它。

## 4. 写作与评审纪律（**文档即门禁**）

1. **每条结论必须有证据**（文件+行号/签名/实测输出）；**未亲见标"未核"**，不得把推测写成结论。
2. **每篇必须写"验收判据"**：哪条门禁/场景/族证明它成立；引用的编号不得悬空。
3. **可复制的片段优先**：能照抄的 YAML/JS/JSON 一律给逐字示例，并注明**前置条件与作用域**。
4. **改动需留痕**：裁决走 01-§5 的 Decision Log；草案升级写版本号与变更点。
5. **一致性**：术语用 01-§7 表；同一概念不得多套叫法；与实现冲突时**先改判定源**（01）。
