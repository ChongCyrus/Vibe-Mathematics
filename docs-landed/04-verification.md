## 2. ★★★★★ 三层验证法（★ 这是**验证一条宣称**的标准做法）

★ **第 1 层：断言【行为】** —— ★ 调它，★ 断言返回的对象**自身的字段** ✓
★ **第 2 层：断言【在多个点上】** —— ★ 若头注说"**每个**""**一律**""**绝不**"，★ **必须测 3–5 个点** ✓
★ **第 3 层：断言【正向】** —— ★★ **负向只能证明它拒了什么；★ 要证明它【不】拒某件事，★ 只能真的让它通过** ✓

### 2.1 ★★★★ 为什么这三层缺一不可（★ 三个实测例子）
★ **例 1**：★ `rules.js` 说"任何表达式形状的东西**都被拒**" ⇒ ★ **只测一个点（`when` 里的 `js` 键）会通过**；★ **测到【规则顶层】的 `js` 键时它就露了** —— ★ **而实测发现它【没拒】** ✓
★ **例 2**：★ `partnership.js` 说"`validateInvoice` **只查槽位存在、★ 不判断税率对错**" ⇒ ★ **只有"税率 999% 但槽位齐 ⇒ 必须【被接受】"才能证明** —— ★ **纯负向测法会在一个"一律拒"的模块上通过** ✓
★ **例 3**：★ `collab.js` 说"**每张**回执带 `fired[]`" ⇒ ★ **测一张会通过**；★ **实测 8 张里 5 张没有** ✓

## 3. ★★★★★ 断言自身的规矩（★ 否则"全绿"毫无意义）

### 3.1 ★★ RULE E：不许写"不可能失败"的断言
★ **五类被判红**：
| ★ 形状 | ★ 为什么红 | ★ 怎么改 |
|---|---|---|
| ★ **A**：`.every`／`for…of` 无**非空守卫** | ★ 空集合时**断言恒真** | ★ **显式写 `.length > 0`**（★ 哪怕数组来自字面量 —— ★ 实测被抓过）|
| ★ **B**：`a.length === b.length` 两侧可能都空 | ★ **两个空集合相等，什么也没测** | ★ 加非空前提 |
| ★ **C / C2**：断言写在 `if` 里 | ★ **分支不跑就跳过，且无别的东西报告** | ★ **把前提提升为无条件断言** |
| ★ **D**：`catch { ok(true) }` | ★ **把抛出的失败当成功吞掉** | ★ 断言具名拒 |
★ **唯一豁免**：★ 语义上就该允许空 ⇒ ★ **在该行附近**写 `// EMPTY_ALLOWED: <为什么空合法，且同一表达式里还有什么能让它红>` ✓

### 3.2 ★★★ 每个探针必须带 `--selftest`
★ **判据**：★ **种一条【故意为假】的断言，★ 它必须红** ⇒ ★ **证明这个探针【能失败】** ✓
★ 那一条要贴 `EMPTY_ALLOWED` 注记，★ 并写明 *"这不是在测模块，★ 是在证明仪器能报错"* ✓

## 4. ★★★★ 三条【读结果】的纪律（★ 本阶段最贵的教训）

### 4.1 ★★★ "一个红是【假设】，★ 不是【发现】"
★ **红了你先怀疑自己**：★ **键名／字段名／方法名**／★ **拒绝是返回还是抛出**／★ **返回的可能嵌在 `refused`/`detail`/`receipt` 下**／★ **方法是 async 吗**／★ **返回值是对象还是字符串**（★ 是字符串就先**解包**）／★ **接缝的类型**（★ 例：`getIndex` 必须返回 **`Map`**）／★ **位置参数 vs 对象参数** ✓
★ **实测**：★ **曾有一条"真缺陷"报告被复现【证伪】** —— ★ 探针自己的 `norm()` 只序列化了 `code`+`message`，★ 却去断言序列化里含 `enforcedScope` ⇒ ★ **模块是对的，★ 探针是错的** ✓

### 4.2 ★★★ "同一种形式，★ 两种相反的对错"
★ **解包一个值**（`JSON.parse(返回的字符串)`）**是对的** ✓
★ **给一个对象造一层 JSON**（把 `{a,b}` 当 `{code,message}` 的替身）**是错的** ✓
★ **区别在于：★ 你在【拆开这个值】，★ 还是在【替换它】** ✓

### 4.3 ★★★ "判断之前，★ 先问这条宣称说的是【哪个面】"
★ **实测**：★ `fidelity` 的 "append-only" **差点被判坏** —— ★ 因为 `view({target})` 只回一条；★ **而留痕在 `trail()`** ✓
★ 而 **`fired` 的语义**更要分清：★ **它是"策略【覆盖】了自然结果"**，★ **不是"策略被用到"** —— ★ **`fired:[]` 意味着策略与自然结果【一致】，★ 没有任何东西被改变** ✓

## 5. ★★★ 怎样加一条新断言（★ 照做即可）
1. ★ **读模块头注**，★ **抄出一句可测量的宣称** ✓
2. ★ **做接缝侦察**（★ 方法名／参数形／返回还是抛出／字段名／会变的字段）✓
3. ★ **按三层验证法写断言**（★ 行为 → 多点 → 正向）✓
4. ★ **过 RULE E**（★ 守卫、不在 `if` 里、非空前提）✓
5. ★ **加 `--selftest`** ✓
6. ★ **登记**：★ `package.json#files` ＋ ★ **重新生成派生面**：
```bash
node scripts/generate-coverage-debt.mjs --write
node scripts/update-doc-counts.mjs
node scripts/regen-all.mjs --write     # 再 --check
GATE_SCOPE=vmu node tests/run-tests.mjs   # 确认 T1 全绿
```

## 6. ★★★ "检查有效"的最终证据
★ **不是"全绿"，★ 而是【它抓到了什么】** ✓
★ **本阶段抓到并修掉 5 处真缺陷**，★ **其中 3 处同一解剖**：★ **"头部把某件事说成【普遍成立】，★ 而实现只在【一部分】上成立"** ✓
