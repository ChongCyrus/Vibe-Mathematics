# 第 04 章 · 流程与协议

**本旨**：描述会议从发起到收束的过程性约定与各方动作。

**本章权威性**：本章是会议流程与会内协议的唯一权威；与本章冲突的任何其它说法一律作废。

> **这份稿子只做策划**：描述"一个会议平台 + 按类型用不同命令"的推荐流程、发言机制、引用语义、表决聚合、时间调控、权限矩阵与反模式。**不含实现细节，不改任何代码/测试/文档。**
> 本章是协议章：允许出现命令名与参数；**实现细节**（数据结构、函数、代码、错误码实现）一律不在本章，见 03／09 章。
> **定位**：辩论、开会、表决统一为**同一个会议平台**；**类型差异只体现在命令与操作上**，不新增"另一套体系"。
> **哲学**：尽可能贴合**现实会议**——有主办方、有议程、有发言秩序、有动议、有表决、有散会与纪要。
> **默认由院士（主办方）驱动**：框架只**推荐**流程、**提示**可选动作，**从不强迫**；任何时刻都会显式提醒院士"**你可以随时调整**：延时、改顺序、换机制、下一步做什么、或直接散会"。
> **命令名**：本稿用建议名（`meeting_*`）。**名字待与 A 稿对齐**；对齐后只改名字，不改语义与流程。

## 1. 统一模型：一个平台，多种操作

现实会议里，"开会"是容器，"类型"只是**议程与规则的不同组合**。平台照此建模：

| 维度 | 说明 | 谁决定 |
|---|---|---|
| 会议（容器） | 一场会议有：题目、目的、参与人、类型、规则、起止时间 | 院士开启/结束 |
| 类型字段 | `debate`（辩论）、`sync`（状况同步）、`discuss`（学术讨论）、`plan`（规划分配）、`org`（组织调整）、`conclusion`（结题表决）、`paper_design`（结题论文设计交流）、可扩展 | 院士设置，可中途改 |
| 流程 | 由**有序步骤**组成；每步＝"用哪个命令 + 期望产出 + 何时收束" | 框架**推荐**，院士采用/删改/跳过 |
| 机制 | 发言机制、群聊模式、引用、计时、表决 | 院士在任一步切换/叠加 |
| 身份 | 院士（主办方）、常驻成员、临时工、受邀者 | 院士邀请/授权 |

**同一平台的三条硬性质**（贯穿全文，是所有机制的底线）：

1. **发言 ≠ 表决**：说话不等于投票；**沉默 ≠ 同意**；**未投票阻塞结题**。
2. **推荐 ≠ 强迫**：框架给流程建议与下一步提示，**永不**自动替院士推进、结束或改变组织决定。
3. **兜底只为防卡死**：框架的自动收束仅用于"没人动、没人答"的死锁场景，且**必须广播它做了什么、为什么**，绝不改变结论本身。

## 2. 各任务类型的推荐流程（对应 D7 会议分级）

> 以下每条流程都遵循同一句式：**步骤 → 用哪些命令 → 何时收束 → 为什么像现实会议**。
> **统一附注（每种类型都适用）**：`院士可随时调整——延时、改顺序、换机制、跳过某步、提前收束或直接散会；框架只做推荐与提示。`

### 2.1 平常会议（`sync` / `discuss` / `plan` / `org`）

**① 研究状况同步（`sync`）**
- 步骤：① 院士 `meeting_open{type:'sync', topic, participants}` → ② 可选 `meeting_flow_set` 采用推荐议程 → ③ `meeting_chat_mode_set{mode:'single', quota:1}`：每人**一次**独立同步（进展/卡点/需要的帮助）→ ④ `meeting_settle`：等在飞发言结束 → ⑤ 院士对要点追问：`meeting_invite`（**邀请内容＋邀请**整体发出）→ ⑥ `meeting_chat_mode_set{mode:'open'}` 自由补充（可限次/禁言）→ ⑦ 院士 `meeting_minutes` 收束要点 → ⑧ `meeting_adjourn`。
- **何时收束**：每人都完成一次独立同步、且追问不再产生新信息；或院士手动收束。
- **为何像现实**：现实中"逐个过一遍近况 + 主办方点名追问 + 自由补充"。

**② 学术讨论（`discuss`）**
- 步骤：① `meeting_open{type:'discuss', topic}` → ② `meeting_chat_mode_set{mode:'single'}`：各自**独立**给出观点与依据 → ③ `meeting_settle` → ④ `meeting_speak_order_set{order}` + `meeting_speak_next`：轮流展开 → ⑤ 成员 `meeting_raise_hand` 请求补充（可**再次**举手）→ ⑥ `meeting_quote` 引用具体观点追论 → ⑦ 院士小结"已达成的共识/仍存分歧" → ⑧ `meeting_adjourn`。
- **何时收束**：分歧点被明确列出（不要求此时解决），或院士宣布转入下一步/散会。
- **为何像现实**：先各自陈述、再轮流发言、允许举手插话、主办方总结。

**③ 任务规划与分配（`plan`）**
- 步骤：① `meeting_open{type:'plan', topic}` → ② `meeting_chat_mode_set{mode:'open'}` 收集候选任务与依赖 → ③ `meeting_settle` → ④ 院士 `meeting_poll_open{options:[候选…], rules:{单选/多选, 最多选几, 最少收集几票}}` 就"优先级/分工范围"取意见 → ⑤ `meeting_chat_mode_set{mode:'single'}` 请每人报"我认领什么、为什么合适" → ⑥ 院士拍板并广播分工（**框架不替院士分配**）→ ⑦ `meeting_minutes` 记录"谁做什么、依据哪轮发言" → ⑧ `meeting_adjourn`。
- **何时收束**：每个任务都有明确归属与依据，或院士宣布"先定这些"。
- **为何像现实**：先议范围、再表态认领、最后主持人宣布分工。

**④ 组织调整（`org`）**
- 步骤：① `meeting_open{type:'org', topic}` → ② 院士说明动因与影响面 → ③ `meeting_chat_mode_set{mode:'open'}` 听取意见 → ④ `meeting_settle` → ⑤ 若涉及取舍：`meeting_poll_open`（选项式）或 `meeting_boolean_vote`（是非式，见 第 4 节）→ ⑥ 院士宣布决定并说明采纳/未采纳哪些意见 → ⑦ `meeting_minutes` + `meeting_adjourn`。
- **何时收束**：决定已作出且理由被记录。
- **为何像现实**：组织调整要先讲清动因、再听意见、最后由主办方拍板（**不是**投票定人事）。

### 2.2 特殊任务会议

**⑤ 辩论（`debate`）** —— 推荐骨架（8 步）

1. `meeting_open{type:'debate', topic, participants, rules}`：院士**定题目/内容/流程/类型字段**（框架给推荐模板，可直接改）。
2. `meeting_chat_mode_set{mode:'single', quota:1}`：**单次发言版群聊**——每位成员**同时、独立**给出初始立场与理由（互不影响）。
3. `meeting_settle`：**沉淀**，等在飞发言全部结束（框架汇报"已完成 x/y，等待 z"）。
4. `meeting_speak_order_set{order:[…]}` + `meeting_speak_next`：**轮流发言**展开辩论（顺序院士自设；默认按自然顺序）；成员可 `meeting_raise_hand` 追加（**可再次举手**）。
5. `meeting_quote{ref}`：引用**具体某条发言**进行反驳或追溯论据（引用链随发言附带）。
6. **自组织**：若分歧仍在收敛，院士**再来一轮第 4 步**（默认推荐；框架只提示"可继续下一轮/可改机制"，不强迫）。
7. `meeting_boolean_vote{prob, reason}`：辩论结束时（院士手动宣布散会/结束），框架**同时**请**每位**成员给出**最终布尔概率估计 + 理由**；**未投票者阻塞结题**。
8. `meeting_adjourn` + 聚合与广播：按 第 4.2 节 聚合后广播
   "**根据研究所规则，由于 …，故最终布尔概率结果更新至 0.6 / 判定结果为 1（或 0）**"，并出纪要。

- **何时收束**：出现明确收敛信号（连续一轮无人提出新论据/反例，或院士判断"可以定论"）；**收束权在院士**。
- **为何像现实**：开场各自陈述、随后轮流交锋、允许举手与点名、最后每人表态并当场汇总宣布。

**⑥ 结题表决（`conclusion`）** —— 推荐骨架（8 步）

1. `meeting_open{type:'conclusion', target, voters, rules{quorumMode, m}}`：院士定**对象**（要结的题）与**表决规则/法定人数**。
2. `meeting_agenda_set{…}`：公布**判定标准与已有材料**（框架给推荐议程：读哪些材料、看哪些证据）。
3. （可选）`meeting_chat_mode_set{mode:'open'}`：自由答疑/讨论（不设限群聊，院士可设每人次数或禁言）。
4. `meeting_settle`：沉淀在飞发言。
5. `meeting_boolean_vote{prob, reason}`：**每位有表决权者**投"布尔概率估计＋理由"（若是选项式议题则用 `meeting_poll_*`，见 第 4.1 节）。
6. **聚合**：第 4.2 节 规则（m 个 1 且无反例 ⇒ 判 1；m 个 0 且无反例 ⇒ 判 0；否则取平均并**更新概率估计**）；**未达法定人数 ⇒ 阻塞**，广播"尚未达法定人数：已投 x/y"。
7. **广播**（模板见附录 B）："根据研究所规则，由于 …，故 …"（含聚合依据与反对意见摘要）。
8. `meeting_adjourn` + 纪要归档：判定/概率/理由/未投票者名单（**未投票必须可见**）。

- **何时收束**：聚合规则给出定论，或院士宣布"本次不结题"（**记录为未定论**，不留悬空）。
- **为何像现实**：先公布标准、再答疑、随后正式表决、当场唱票并宣布结果（含异议）。

**⑦ 结题论文设计交流（`paper_design`）**
- 步骤：① `meeting_open{type:'paper_design', target}` → ② 院士公布论文的**结构与证据要求** → ③ `meeting_chat_mode_set{mode:'single'}`：每人独立提交"我认为该写什么、缺什么证据" → ④ `meeting_settle` → ⑤ `meeting_speak_order_set` + 轮流：逐节讨论（框架可按节提示"当前讨论第 k 节"）→ ⑥ 分歧点用 `meeting_poll_open`（选项式，例如"是否收录某条未定论结果"）→ ⑦ 院士定稿要点 + `meeting_minutes` → ⑧ `meeting_adjourn`。
- **何时收束**：各节都有明确结论或"待补证据"清单。
- **为何像现实**：论文讨论本就按"结构逐节过 + 主办方定稿"。

**⑧ 可扩展类型**：新类型 = 新的一组**推荐流程 + 默认规则**，机制与命令**复用**（这就是"一个平台"的价值）。

### 2.4 同一议题的并发约束（**对应定稿 G4**）

- **决议类**会议（会产出实体定论／表决的会议：结题表决、以辩论收敛结论者）在**同一议题**上**同一时刻只允许一场**；出现冲突时**以先开者为准**，后开者**不得**就该议题继续表决流程。
- 冲突必须**显式通知**后开者及其主办方：通知**具名**并**记入后开会的纪要**，**不得静默**。
- **讨论类**会议（研究状况同步／学术讨论／任务规划／组织调整）**可以并行**，但并行会议**不得**就同一议题产出实体定论。
- 依据：同一问题产出两套结论是研究组织最危险的失真之一；本条的会议级约束与"决议类互斥"同源。
> 过程性计票与结束裁定的分离要求（过程票数只是当时描述、不得据此停止/收束/切换阶段；过程计票须标「尚未生效·仅供参考」）见 **05 章 第 4.7 节**（对应定稿 R10）。

### 2.3 流程的共同性质

- 每步都可**跳过、重排、重复、合并**；院士的显式命令是唯一切换来源。
- 框架在每步**提示**："可继续下一步 / 可再来一轮 / 可换机制 / 可收束"，并**同时**提示"院士可随时调整"。
- 收束准则只有两条：**信息不再增长**（新论据/新信息停止出现）或**院士宣布收束**。

## 3. 发言机制（六种）与组合

| 机制 | 命令（建议名） | 语义 | 关键细节 |
|---|---|---|---|
| **举手发言** | `meeting_raise_hand` | 成员示意"我要发言" | **可再次举手**（同一轮/不同轮都可以）；框架按举手顺序维护队列，**由院士决定何时/是否点** |
| **按顺序点名发言** | `meeting_speak_order_set` + `meeting_speak_next` | 院士自设顺序，逐一请人发言 | 默认**自然顺序**（名册序/上一轮顺序）；点到的成员获得本轮发言权 |
| **邀请发言** | `meeting_invite{to, content}` | 院士点名某人就**特定内容**发言 | **"邀请内容 ＋ 邀请"是一个整体**：内容字段必填，避免"随便说两句" |
| **沉淀/等待** | `meeting_settle` | 等待在飞发言全部结束 | 框架汇报进度（x/y、还在等谁）；**不是**"催发言"，而是"先把话说完整" |
| **不设限群聊** | `meeting_chat_mode_set{mode:'open', params}` | 像交流群，可**同时**发言 | 院士是**管理员**：可设"每人可发信息次数""禁言名单""是否允许引用" |
| **单次发言版群聊** | `meeting_chat_mode_set{mode:'single', quota:1}` | **每人一次**，用于**初始同时独立发言** | quota 默认 1；"单次"是**本轮**每人一次，**不是**整场只能发一次 |

**切换与叠加规则**

1. **开局**用 `single`（各自独立，避免从众与互相带节奏）。
2. **展开**用"轮流/点名 + 举手"（有序交锋）。
3. **自由讨论/头脑风暴**用 `open`（可限额、可禁言）。
4. **任何时刻**院士可 `meeting_chat_mode_set` 切换或 `meeting_speak_order_set` 重排；切换会**广播**"发言机制已改为 …（原因：…）"，避免成员以为"轮到自己了"。
5. **叠加**：`settle` 可与任何模式叠加（"等说完再切"）；引用在任何模式下都可用（第 3 节）。

## 4. 引用（quote）语义（对应 D6 引用边界）

**是什么**：发言可以**引用过去某一条发言**（像聊天里"@某条消息"），把被引内容一并附上。命令：`meeting_say{content, quote_ref}`（或"发言"命令的 `quote_ref` 字段）。

**在辩论里怎么用**
- **反驳具体论点**：引用对方原话，指出其前提/推理/证据的问题（避免"稻草人"）。
- **追溯论据**：引用早前给出的定义、数据、引理，说明自己继承/依赖什么。
- **收敛信号**：当引用开始重复、不再指向新论据时，就是"该收束了"的现实信号。

**避免刷屏/循环引用**
- 每条发言**建议最多引用 1–2 条**（院士可设上限）。
- **禁止纯引用无新增**：只引用不复述观点、不提出理由的发言，视为"无新增信息"（框架可标注"本条无可判定新增"）。
- **环形引用检测**：A 引 B、B 引 A 且都不含新论据时，框架提示"引用成环，请补充新论据或转为一句话表态"。
- 引用链**深度**有上限（默认 3；院士可调），超深时折叠为"见第 k 轮发言 #n"。

**纪要与摘要里怎么呈现**
- 纪要中引用以**锚点**形式呈现：`第 k 轮 · 发言 #n · <发言人>` + 被引原文摘句（限长）。
- 摘要保留**引用链**（谁在反驳谁），但**不复制**长正文；分歧点按"论点 → 反驳 → 现状（未决/已决）"排列。

## 5. 表决与聚合协议（对应 R9／C3，另见 R10）

> **底线**：**表决与发言分离**——说话不等于投票；**沉默 ≠ 同意**；**未投票阻塞结题**。未投票者在结算时**必须可见**（名单＋数量）。

### 5.1 普通投票板（选项式）

- 命令：`meeting_poll_open{question, options, rules}` → 成员 `meeting_poll_vote{poll, choices}` → 院士 `meeting_poll_close`。
- **规则字段（院士设）**：单选/多选；**最多**选几项；**至少**选几项；**最少收集**几票（门槛）；是否允许改票（默认允许、以最后一次为准）；是否需要理由（可选）。
- **计票**：
  - **有效票**：符合选项范围与"最多/至少"约束；
  - **无效票**：越界选项、超出上限、重复选同一项 → 记为无效并**注明原因**（不静默丢弃）；
  - **未达门槛**：收集票数 < 最少收集 ⇒ **不产生结论**，广播"未达门槛：x/y，本次不形成结论"（**不得**按剩余票推断）。
- **呈现**：得票表 + 有效/无效/未投（名单）+ 结论（若有）+ 理由摘要。
- **为何像现实**：现实投票有"规则先讲清、无效票要说明、人数不够就流会"。

### 5.2 布尔概率表决（辩论/结题）

- 命令：`meeting_boolean_vote{prob, reason}`：**投所辩论内容的布尔概率估计**（0…1，允许 0.5 等中间值）**＋阐明理由**。
- **聚合规则（按研究所规则）**：
  1. 设投出的估计为 `p_i`，其中"判 1"= `p_i = 1`，"判 0"= `p_i = 0`，其余为**概率估计**。
  2. 若有 **m 个 1 且无 0**（或 **m 个 0 且无 1**）⇒ **最终判定 = 1（或 0）**（允许其余成员给出 0…1 的概率估计）。
  3. 否则 ⇒ **取平均**并**更新概率估计**（把新的平均概率作为该题当前的概率估计写入记录），**不给出布尔判定**。
  4. **未达法定人数**（未投票）⇒ **阻塞结题**，广播"未投票阻塞：已投 x/y，需全部/达 m"。
- **并列/矛盾/参与不足**：
  - **矛盾**（同时存在 1 与 0 且都达 m）⇒ **不得定论**，广播分歧并列出双方理由（院士可再开一轮辩论或宣布未定论）。
  - **参与不足**（有效票 < 法定人数）⇒ 阻塞，不产生判定。
  - **并列**（选项式平票）⇒ 不自动裁决，交由院士（可 `meeting_poll_open` 复投或宣布未决）。
- **广播文案模板**（附录 B 有完整版）：
  "**根据研究所规则，由于〔聚合依据：如"m 位成员判真且无反例" / "无一致群组，取平均"〕，故最终布尔概率结果更新至〔0.6〕/判定结果为〔1（或 0）〕。**"

### 5.3 表决的独立性与顺序

1. 先 `meeting_settle`（把话说完）**再**表决；表决期间**不夹带**新的辩论发言（避免用发言影响计票）。
2. 表决可**匿名或具名**由院士选择；默认**具名**（可追溯、可审计），匿名仅用于避免压力。
3. 结果一旦广播即**同时写入纪要**；改票窗口由院士设定（默认到 `meeting_poll_close`/聚合前一刻）。
4. **未投票**永远是"阻塞 + 可见"，**绝不被当作 0/1/同意**。

## 6. 时间、停止与实时调控（对应 D4 延长有界／R10 停止来源）

**院士可设**（按命令/按机制）：每步时长、每机制时长、何时停止、是否自动进入下一步（**默认不自动**）、是否允许改票、是否允许延时。

| 参数（建议名） | 含义 | 建议默认 | 备注 |
|---|---|---|---|
| `step_duration` | 单步时长（如"轮流发言每人 ≤N 分钟"） | 无（不设硬限，仅提示） | 院士显式设置才生效 |
| `mechanism_duration` | 单机制总时长（如"本轮群聊 ≤N 分钟"） | 无 | 到期仅**提示**，不自动切 |
| `speak_time_per_member` | 每人单次发言时长 | 无 | 超时提示"可继续/可请下一位" |
| `settle_timeout` | 沉淀等待上限（防在飞卡死） | 有（兜底，见下） | 到期广播"仍在等待 x/y"并**询问院士** |
| `vote_window` | 表决收集窗口 | 无（由院士关闭） | 到期**不自动结算** |
| `quote_depth_max` | 引用链深度上限 | 3 | 超深折叠 |
| `quotes_per_message_max` | 单条发言引用上限 | 2 | 防刷屏 |
| `open_chat_quota` | 不设限群聊每人次数 | 不限（可设） | 院士=管理员 |
| `mute_list` | 禁言名单 | 空 | 可随时加/解 |
| `allow_revote` | 是否允许改票 | 是（以最后一次为准） | 结题表决可关 |

**实时调控**：`meeting_extend{step|mechanism, +时长}`（延时）、`meeting_flow_set`（改流程/重排）、`meeting_chat_mode_set`（换机制）、`meeting_stop{scope}`（停某步/整场）、`meeting_adjourn`（散会）。

**与"硬界兜底"的关系（必须写清）**
- 框架的自动动作**只有一类**：**防卡死**（没人发言、没人在飞、无人应答的静止状态）。
- 兜底动作必须**广播**："因〔原因〕，框架执行了〔动作〕；**院士可随时撤销/调整**"。
- 兜底**不得**：替院士结束会议、替院士做组织决定、把未投票当同意、把未达门槛当通过、自动产生判定。
- 硬界是**上限**（防无限等待），不是**目标**（不追求"到点就推进"）。

**临时授权的典型用例**

## 8. 反模式清单（现实问题 ↔ 机制性防范）

| 现实会议问题 | 平台里的机制性防范 | 为何仍需院士判断 |
|---|---|---|
| **跑题** | 议程字段 + 每步"期望产出" + 框架提示"当前步骤与议题的偏离度" | 是否真的跑题、是否值得临时改题，只有院士能定 |
| **冷场/无人发言** | `single` 模式强制每人一次；`raise_hand` 队列；`invite` 点名邀请（带内容） | 是"该等人"还是"该换机制/点名"，由院士决定 |
| **少数人垄断** | `single` 开局（独立发言）＋ 每人次数配额 ＋ 发言顺序自设 ＋ 举手队列 | 谁是"必须发言的关键人"，需院士判断 |
| **刷屏** | 引用上限、纯引用无新增标注、群聊次数配额、禁言名单 | 哪些发言属于"有效但重复"，需院士裁量 |
| **循环引用/扯旧账** | 引用深度上限、环形引用提示、折叠为锚点 | 是否"旧账仍相关"，由院士判断 |
| **程序性动议被忽略** | 举手队列**不可被静默丢弃**（框架必须呈现队列与未处理项）；流程切换必须广播 | 是否采纳动议、何时打断当前议程，由院士决定 |
| **表决被操纵** | **发言与表决分离**（表决期间禁止夹带发言）；无效票注明原因；未投票阻塞且可见；改票以最后一次为准并可选择是否允许 | 是否重开表决、是否认定某票无效，由院士（并留痕）决定 |
| **沉默当成同意** | **硬性禁止**：沉默≠同意；未投票**阻塞**结题并广播"已投 x/y" | ——（这条不是裁量，是底线） |
| **"到点自动通过"** | 过期只**提示**、不自动结算；硬界兜底只防卡死且必须广播 | 延时/收束的时机由院士定 |
| **结论无依据** | 每次广播**必须**带"由于 …"（聚合依据 + 反对意见摘要）；纪要与引用链留痕 | 依据是否充分，由院士与成员判断 |
